Durable Workflow і Temporal

Стійке виконання для PHP, Python та Rust на знайомому серверному стеку.

Durable Workflow — рушій workflow з відкритим кодом. Ваш застосунок запускає worker для workflow й activity на PHP, Python або Rust. Server відповідає за надійне зберігання історії, розподіл завдань, timer та відновлення. Вашому застосунку Laravel не потрібен.

Запускайте Server як окремий сервіс із опублікованого контейнера, а застосунок і worker залишайте у власному мовному середовищі та середовищі розгортання. Можна використовувати одну мову або поєднувати worker різними мовами. Розробники PHP отримують workflow на основі Fiber та worker, який запускається безпосередньо, без RoadRunner.

Temporal використовує спеціалізований сервіс оркестрації та має ширший вибір SDK. У PHP його API для workflow використовує генератори, а worker працюють через RoadRunner. Вибір залежить від потреб застосунку та відповідальності за експлуатацію.

Обіцянка Durable Workflow — передбачувана вартість, передбачувана поведінка та передбачувана експлуатація: інфраструктура з планованим бюджетом, явні контракти виконання та історія workflow, яку можна дослідити.

Один Server, три офіційні SDK​

Ви можете писати workflow й activity на PHP, Python та Rust. Worker працюють у середовищі вашого застосунку, підключаються до Server та масштабуються незалежно від нього.

Команда Python може залишити весь застосунок на Python. Команда Rust може залишити весь застосунок на Rust. Мова реалізації Server не стає залежністю застосунку.

Мови можна поєднувати й у межах одного workflow. Приклад із запуском кількох мов використовує workflow на PHP, activity обчислення на Python та activity квитанції на Rust в окремих чергах завдань. Рушій координує їх через іменовані типи workflow й activity.

Temporal пропонує SDK для ширшого набору мов. Для застосунку на Go, Java, .NET, Ruby або TypeScript така підтримка є конкретною причиною обрати Temporal.

Послідовний PHP-код без RoadRunner​

PHP SDK Durable Workflow використовує керований Fiber. Виклик $context->activity(...) призупиняє виконання workflow, доки стійкий результат не стане доступним. Потім метод продовжується з цим результатом. Ваш workflow залишається послідовним PHP-методом зі звичайним типом повернення. У коді workflow не потрібно використовувати yield чи типи повернення Generator.

Worker запускається безпосередньо командою php worker.php. Його HTTP-транспорт PSR-18 не потребує ані RoadRunner, ані розширення gRPC.

API workflow на PHP у Temporal виражає призупинення через генератори й yield. Його налаштування PHP включає RoadRunner та розширення gRPC.

Ось повний файл обробників Durable Workflow для режиму сервісу. Workflow планує activity привітання та повертає її результат:

handlers.php
<?php

declare(strict_types=1);

use DurableWorkflow\Attribute\Activity;
use DurableWorkflow\Attribute\Workflow;
use DurableWorkflow\Worker\ActivityContext;
use DurableWorkflow\Worker\WorkflowContext;

final class GreetingWorkflow
{
    #[Workflow('comparison.php.greeting')]
    public function run(WorkflowContext $context, string $name): array
    {
        return ['greeting' => $context->activity('comparison.php.greet', [$name])];
    }
}

final class GreetingActivities
{
    #[Activity('comparison.php.greet')]
    public function greet(ActivityContext $context, string $name): string
    {
        return "Hello, {$name}!";
    }
}

Завантажте worker, клієнт і тест. У цьому каталозі, маючи PHP 8.1+ та Composer, виконайте:

composer install
php test.php

Тест перевіряє реєстрацію, планування та виконання activity, а також відтворення із записаним результатом activity. Щоб запустити worker і клієнт із реальним середовищем виконання, запустіть локальний Server за адресою http://localhost:8080 з документованим токеном розробки, а потім виконайте php worker.php та php client.php в окремих терміналах:

{"greeting":"Hello, Ada!"}

Ми перевірили цей результат з опублікованими SDK та Server. Версії та результати тестів записано разом із вихідним кодом.

Передбачувана поведінка між worker​

Обидва рушії відновлюють стан workflow із записаної історії. Результати завершених activity відтворюються в коді workflow без повторного виконання вже завершеної роботи. Тому рішення workflow мають залишатися детермінованими: мережеві виклики та зміни бази даних розміщуйте в activity, а для часу використовуйте стійкі API timer і часу. Дивіться модель виконання Durable Workflow та відтворення workflow у Temporal.

Доставка activity — окреме питання. Worker може виконати зовнішню дію та завершитися з помилкою до повідомлення результату, тож повторна спроба може повторити цю дію. Durable Workflow надає стабільну логічну ідентичність виконання activity між спробами. Її можна використовувати як ключ ідемпотентності для платежів та інших зовнішніх ефектів. Гарантії виконання пояснюють цей контракт. Temporal також рекомендує ідемпотентні activity.

Спільний контракт даних​

SDK Durable Workflow для PHP, Python та Rust використовують спільний фіксований контракт Avro Value. Він зберігає між мовами відмінності, зокрема між байтами й текстом та між цілими числами й числами з рухомою комою. SDK містять схему, тож вам не потрібно експлуатувати реєстр схем. Об’єкти застосунку адаптуються до цих переносимих значень.

Temporal використовує Data Converters із типовою серіалізацією та підтримкою власних конвертерів і кодеків. Durable Workflow обирає більш визначений підхід: один переносимий контракт значень для всіх офіційних SDK.

Для впевненості в розгортанні перевіряйте зміни workflow на записаній історії, а також тестуйте бізнес-логіку activity. Durable Workflow надає тести відтворення PHP SDK та тестові підміни вбудованого режиму. Temporal документує свої засоби модульного та інтеграційного тестування PHP.

Самостійне розгортання на знайомому стеку застосунків​

Запуск Durable Workflow Server означає запуск застосунку Laravel. Він використовує налаштування PHP-застосунку, базу даних, сервіси черг і кешу, а також процеси worker та планувальника. Оператори, знайомі з Laravel, можуть застосувати свої навички для розгортання, журналювання, нагляду за процесами та обслуговування бази даних.

Вихідний код Server та посібник із розгортання дозволяють дослідити це налаштування. Опублікований Docker-образ уже містить застосунок. Його використання не вимагає PHP чи Laravel у середовищі ваших worker на Python або Rust.

Опубліковане налаштування Compose для Durable Workflow використовує MySQL та Redis. Локальний швидкий старт також підтримує SQLite. Посібник із самостійного розгортання Temporal описує варіанти розгортання. Локальний сервіс розробки доступний через Temporal CLI.

Передбачувана вартість випливає з явної відповідальності. Рушій Durable Workflow, Server та Temporal Server мають ліцензію MIT. Самостійне розгортання будь-якого рушія не передбачає плати за кожну дію в програмному забезпеченні. Ваші витрати — це інфраструктура та її експлуатація. Durable Workflow дозволяє використовувати усталені інструменти PHP-застосунків і незалежно масштабувати worker мовою вашого застосунку.

Дослідження історії workflow​

Waterline показує історію виконання Durable Workflow, результати activity, timer та помилки. Він може працювати як окремий операторський інтерфейс для Server або всередині застосунку Laravel для вбудованого виконання. CLI та Server API також відкривають стан середовища виконання. Temporal надає вебінтерфейс для дослідження виконань та історії.

Інтеграція з Laravel, якщо застосунок використовує Laravel​

Користувачі Laravel мають два варіанти: вбудувати рушій або залишити окремий Server і використовувати міст Laravel у PHP SDK. Міст надає обробники, які отримуються з контейнера, налаштування, журналювання, команду Artisan для worker та тестову підміну. Відокремлення стану оркестрації не вимагає відмовлятися від звичних правил фреймворку застосунку.

Вбудовування йде далі: стан workflow зберігається в базі даних застосунку, а worker черг Laravel виконують роботу. Ви розгортаєте рушій разом із застосунком, замість експлуатації окремого сервісу. Почніть із посібника встановлення вбудованого режиму.

Який рушій підходить вашій команді?​

Обирайте Durable Workflow для застосунків на PHP, Python та Rust, якщо вам потрібен рушій для самостійного розгортання зі спільним міжмовним контрактом виконання та незалежно розгорнутими worker застосунку. Команди PHP також отримують workflow на основі Fiber без RoadRunner і необов’язкову інтеграцію з Laravel.

Обирайте Temporal, якщо його ширша підтримка мов у SDK або ваші наявні інструменти та досвід Temporal краще відповідають застосунку.

Почніть розробку: оберіть швидкий старт для PHP, Python чи Rust, запустіть Durable Workflow Server або дослідіть SDK Temporal.
