客户端与 Worker 能力

根据进程需要执行的任务选择接口。dw CLI 与第一方 PHP、Python 和 Rust SDK 共享 v2 控制平面及 Worker 契约，但其运维、客户端和 Worker 角色并不相同。

这份覆盖所有客户端的指南保留原有的 /docs/polyglot/cli-python-parity/ 路由，使现有链接继续有效。

各产品接口的证据​

CLI​

CLI 概览 定义安装、配置档、结构化输出及退出行为。命令参考 是完整的运维接口，包括生命周期、消息、调度、可观测性，以及有意区别于 SDK Worker 循环的底层 Worker 协议命令。

PHP SDK​

固定版本的 PHP SDK 提供框架无关的客户端与远程 Worker API。其当前公开接口包括工作流生命周期及结果句柄、信号、查询、更新、调度、工作流过滤/历史、命名空间、Worker 和任务队列可观测性，以及已注册的工作流、活动、查询和更新处理器。参见 PHP SDK 指南 与生成的 PHP API 参考。

Python SDK​

Python SDK 将异步控制平面客户端与确定性工作流及活动 Worker 结合。其指南提供客户端操作、消息处理器、Worker 执行 和调度管理。生成的 Python API 参考 包含精确签名和结果类型。

Rust SDK​

已发布的 Rust SDK 提供控制平面及选定运行的生命周期、信号、经重放的查询、更新，以及原生工作流/活动 Worker。更新支持包括 Client::update_workflow、WorkflowHandle::update、Worker::register_update 及其 Avro 值变体。调度管理和整个集群的列表/搜索仍是明确的缺口。参见 Rust SDK 指南 与生成的 Rust API 参考。

共享契约证据​

四个产品都面向相同的带版本 HTTP+JSON 控制平面及公开载荷信封。证据按其证明内容划分：

  • 能力索引 记录精确的制品最低版本及当前覆盖范围；
  • 平台一致性套件 记录跨客户端、跨 Worker 的运行时场景；
  • CLI 和 Python 仓库保留共享请求样例，针对目前按字节比较语义请求体的操作；
  • PHP 和 Rust 公开 API 参考及发布测试证明上方所列的其他受支持方法。

两个仓库存在共享样例，不代表其他 SDK 缺少该操作。反过来，共同的端点也不代表每个产品提供相同的运维或 Worker 角色。

添加或扩展客户端接口​

新增 CLI 或 SDK 操作时：

  1. 保持路径、方法、语义字段、载荷信封及错误结果与语言无关。
  2. 为每个参与的客户端或 Worker 添加请求与运行时证据。
  3. 记录有意不同的语法或角色边界。
  4. 明确标记不受支持的产品。
  5. 将语言专属的序列化、文件路径、类名或错误结构视为公开契约中的缺陷。
