Server 配置参考

本页说明 Durable Workflow Server 镜像面向运维人员的 DW_* 环境变量契约。构建部署模板、检查生产配置，或将旧的 WORKFLOW_* / ACTIVITY_* 名称迁移到 v2 Server 契约时，请参考本页。当前 Server 是原生 3.x Server；原生 Server 3.x 列出它遵循、忽略或拒绝的设置。PHP Server 2.x 已冻结在 2.11.8。

PHP 2.x Server 还使用常规 Laravel 运行时设置，例如 DB_*、REDIS_*、QUEUE_CONNECTION 和 CACHE_STORE。这些变量属于部署基础设施，并非 Durable Workflow API 控制项，因此单独列出。

原生 Server 3.x​

本页的变量表记录 PHP Server 2.11.0 发布的 DW_* 契约，其用途说明描述的是 PHP 2.x。原生 3.x Server 读取相同的名称及相同的旧版别名，并通过启动审计为每个契约设置确定一种处置方式：

  • 遵循： 原生 Server 读取该设置并采用 PHP 中的含义。下文未列出的设置均被遵循。
  • 忽略： 原生 Server 接受该设置，但它不会改变客户端或运维人员可观察到的任何行为。
  • 非默认值即拒绝： 除非该设置未设置或保持 PHP 默认值，否则原生 Server 拒绝启动。启动错误会给出该设置、可接受的值以及原因。

原生 Server 只在进程启动时读取一次环境，并且不保留配置缓存。要更改设置，请重启或替换 Server 进程。与 PHP 的 env:audit 一样，原生审计会对未知的 DW_* 名称和旧名称发出警告；设置 DW_ENV_AUDIT_STRICT=1 后，这些警告会变为拒绝启动。

原生 Server 没有服务器端任务队列租约上限或派发上限、预算组、命名空间请求准入、命名空间持久状态配额或保持中轮询上限，目前也没有对应的原生替代方案。每个原生 Server 进程最多打开四个数据库连接。查询任务有固定上限：每个命名空间最多16个待处理或已租用的任务，超出后新查询会与 PHP 一样以 HTTP 429 和 query_task_queue_full 被拒绝；该上限不可配置。要在原生 Server 上限制任务并发，请调整每个 SDK Worker 的执行槽数量和 Worker 数量。PHP 2.x 的控制项见任务队列准入。

原生 Server 的身份验证与 PHP 2.x 有以下不同：

  • DW_AUTH_TOKEN 为必需项。缺少它时原生 Server 拒绝启动；它对每个角色都接受该共享令牌，同时也接受任何按角色划分的令牌。
  • DW_AUTH_DRIVER 只接受 token。原生 Server 拒绝 signature，发布镜像还会拒绝 none。签名密钥相关设置会被忽略。

原生 Server 还读取 PHP 契约之外的设置：

  • DW_BIND_ADDRESS：监听地址。二进制文件默认为 127.0.0.1:8080；已发布镜像设置为 0.0.0.0:8080。
  • DW_RUST_MAINTENANCE_LOOP：设为 1 或 true 时，会在进程内定时器与调度循环中加入修复过程（任务修复和活动超时）。已发布镜像设置为 1，因为它没有独立的调度器。
  • DW_RUST_EXPERIMENTAL：仅没有发布版本的开发构建要求设为 1。发布镜像无需设置。
  • DW_UPGRADE_BACKUP_FINGERPRINT 和 DW_RUST_UPGRADE_QUEUE_*：对 PHP 数据库执行单向 原生接管 时的输入；该接管已在运行手册说明的范围内于已发布的 3.0.4 镜像上通过资格验证。
  • DW_V2_LIMIT_HISTORY_TRANSACTION_ROWS（旧名称 WORKFLOW_V2_LIMIT_HISTORY_TRANSACTION_ROWS）：在加入 PHP 契约之前即已被遵循。

配置变更何时生效​

原生 3.x 只在进程启动时读取环境；要应用变更，请重启或替换 Server 进程。本节其余内容描述 PHP 2.x。

已发布的 PHP Server 镜像在入口脚本中运行 php artisan config:cache。环境值在启动时解析并写入 Laravel 配置缓存。修改环境文件、编排器中的环境声明或挂载的配置文件，都不会使运行中的部署热加载配置。

使用新配置重启或替换所有受影响的进程，包括 HTTP API 副本、本地 Laravel 队列 Worker 和调度器。修改 SDK 客户端或 Worker 自身配置时，另行重启长期运行的 SDK Worker。API 重启成功并不会更新仍在运行的队列 Worker 或调度器。共享数据库与缓存的各角色应使用一致的预期配置。

滚动变更期间，每个节点执行自己已加载的限制。共享准入计数器无法让配置不同的节点自动采用相同限制，因此某个 API 副本接受的请求可能被另一个拒绝。需要一致切换限制时：

  1. 暂停调用方提交新请求，并从入口移除受影响的 API 副本。让在途请求完成，按照各自的关闭时间预算正常停止队列与调度器角色。
  2. 向所有受影响角色应用相同配置，然后重启或替换它们。让各容器入口脚本重建配置缓存。
  3. 检查启动日志中的配置错误、确认就绪状态，并实际验证变更的限制，然后恢复入口流量和调用方提交。参阅部署与就绪指南。

存储在数据库中的运维设置采用不同生命周期。以下修改成功后，后续操作即可使用新值，无需重启 Server：

设置即时修改范围与限制
命名空间描述与保留PUT /api/namespaces/{namespace}，或 dw namespace:update保留策略作用于后续清理。更改策略不能恢复已剪除的数据。参阅 Server 保留设置。
命名空间外部载荷存储策略PUT /api/namespaces/{namespace}/external-storage更改持久化的命名空间策略。提供方凭据、已配置的文件系统磁盘及其他进程配置仍需按照上述流程重启。保留对现有运行所引用对象的访问。
命名空间搜索属性定义POST / DELETE /api/search-attributes更新后续请求使用的注册信息，不改写工作流历史，也不替代环境配置的大小和数量限制。

除非文档明确说明某个控制平面操作会修改持久化状态，本页的 DW_* 默认值和上限都属于进程配置。Server 不会轮询配置文件的变化。

契约如何执行​

Server 仓库在 config/dw-contract.php 中维护规范契约。原生 3.x 在启动时执行等效审计，详见原生 Server 3.x。在 PHP 2.x 上，容器启动时，php artisan env:audit 会对未知的 DW_* 变量或旧名称发出警告。如需让入口脚本直接失败而不是带警告启动，请设置 DW_ENV_AUDIT_STRICT=1。

DW_ENV_AUDIT_STRICT=1
DW_AUTH_DRIVER=token
DW_ADMIN_TOKEN="${DW_ADMIN_TOKEN}"
DW_OPERATOR_TOKEN="${DW_OPERATOR_TOKEN}"
DW_WORKER_TOKEN="${DW_WORKER_TOKEN}"

旧名称仅用于回退。新部署优先使用 DW_* 名称。即使 Server 仍接受旧值，也应将旧名称警告视为待完成的迁移工作。

配置 DW_V2_MATCHING_ROLE_QUEUE_WAKE 或专用 workflow:v2:repair-pass --loop 守护进程时，请参阅任务匹配与分派。这些设置改变就绪任务的发现位置，而不改变 Worker 协议本身的契约。

运行基础设施变量​

运行基础设施变量属于框架及依赖项控制。Server 审计认识这些变量，因此不会发出警告，但它们不是稳定的 Durable Workflow API 配置项。原生 3.x 读取数据库分组，包括下文的 TLS 设置。它没有 Redis、缓存或 Laravel 队列，将日志写入标准错误输出，并且不读取 LOG_CHANNEL 或 LOG_LEVEL。

分组变量用途
应用APP_NAME、APP_ENV、APP_KEY、APP_DEBUG、APP_URL、APP_VERSION、区域、时区、维护及加密设置Laravel 应用的运行时标识与启动行为。
日志LOG_CHANNEL、LOG_LEVEL、LOG_STDERR_FORMATTER、堆栈、每日、Slack 与 Papertrail 设置Laravel 日志输出位置、格式与保留。
数据库DB_CONNECTION、DB_HOST、DB_PORT、DB_DATABASE、DB_USERNAME、DB_PASSWORD、DB_SOCKET、DB_URL、DB_SSLMODE（DB_SSL_MODE）、DB_SSLROOTCERT（DB_SSL_ROOT_CERT）、MYSQL_ATTR_SSL_CA、字符集、排序规则及外键设置存储工作流、命名空间、Worker 及投影表的 SQL 状态库。参见数据库 TLS。
Redis、缓存与队列REDIS_*、QUEUE_CONNECTION、QUEUE_FAILED_DRIVER、CACHE_STORE、CACHE_PREFIX、SESSION_*队列 Worker、缓存锁、长轮询信号和 Web/会话运行时支持。
文件系统、邮件与广播FILESYSTEM_DISK、MAIL_*、BROADCAST_*、PUSHER_*、AWS_*部署特有功能使用的框架集成。
构建与运行时MYSQL_VERSION、REDIS_VERSION、PHP_CLI_SERVER_WORKERS、VITE_APP_NAME、BCRYPT_ROUNDSDocker Compose 镜像及框架运行行为。

数据库 TLS​

原生 3.x 以与 PHP 2.x 相同的方式解析这些设置：相同的输入、别名、模式名称和拒绝规则。它只需配置一个 Server 进程，以及针对同一数据库运行的任何 schema-upgrade 或接管命令。在 PHP 2.x 上，为 API 服务器、队列 Worker、初始化/迁移任务和调度器配置相同的 TLS 设置。PostgreSQL 默认为 prefer；MySQL/MariaDB 未指定模式时保留原有连接默认值。这些默认值都不能保证经过身份验证的加密连接。

DB_SSLMODEPostgreSQLMySQL / MariaDB
disable不使用 TLS。不使用 TLS；拒绝冲突的 TLS 选项。
allow, prefer机会式 TLS，不保证加密或身份验证。拒绝。
require必须加密。必须通过 mysqlnd 和 OpenSSL 加密。
verify-ca必须加密并验证受信任的证书链。拒绝：PDO mysqlnd 无法脱离主机名验证而单独验证证书链。
verify-full必须加密、验证受信任的证书链并匹配主机名。必须加密、验证受信任的证书链并匹配主机名。

DB_SSL_MODE 是 DB_SSLMODE 的别名，DB_SSL_ROOT_CERT 是 DB_SSLROOTCERT 的别名。验证证书时，应在 每个角色（包括迁移任务）中，将可读的 CA 文件挂载到 配置的路径。MySQL/MariaDB 显式使用 verify-full 时，也可用 MYSQL_ATTR_SSL_CA 提供 CA。规范变量、别名或 URL 设置冲突会阻止启动。必须使用 TLS 时，需要明确的 TCP 主机名，不能使用 Unix 套接字。MySQL/MariaDB 的显式 TLS 模式需要带有 mysqlnd 和 OpenSSL 的 PDO MySQL。

DB_CONNECTION=pgsql
DB_HOST=database.example.com
DB_SSLMODE=verify-full
DB_SSLROOTCERT=/run/database-ca/ca.pem

使用证书中的 DNS 主机名。Helm 部署应配置 externalDatabase.sslMode 和 externalDatabase.tls.existingSecret / caKey。安装或升级前先创建 Secret； chart 会将其 CA 挂载到全部四个角色，包括初始化钩子。 环境设置更改后应重启常驻角色，因为启动时会缓存配置。

容器日志​

原生 3.x 始终将日志写入标准错误输出。在 PHP 2.x 上，在 API、worker 和调度器容器中设置 LOG_CHANNEL=stderr，让 docker logs 或 kubectl logs 收集应用日志。已有发行版需显式设置。使用 LOG_LEVEL 选择最低严重级别。如需每行一条记录的 JSON，还应设置：

LOG_STDERR_FORMATTER="Monolog\Formatter\JsonFormatter"

配置会在启动时缓存，因此修改后应重启常驻进程。显式选择文件日志通道时， 需要自行提供存储和收集机制；Kubernetes 不会自动收集 storage/logs/laravel.log。DW_LOG_FORMAT 不是受支持的设置。

迁移说明​

迁移旧部署时，先改用公开名称，并将旧名称设为未设置。若两者同时存在，运维人员应以 DW_* 值为准，并移除旧名称。

# Before
WORKFLOW_SERVER_AUTH_DRIVER=token
WORKFLOW_SERVER_OPERATOR_TOKEN=operator-secret

# After
DW_AUTH_DRIVER=token
DW_OPERATOR_TOKEN=operator-secret

迁移后以 DW_ENV_AUDIT_STRICT=1 启动 Server 镜像，检查拼写错误、过时别名和从旧运行手册复制的设置。
