API de workflow

Esta página contiene la referencia completa. Para una lectura más sencilla, consulta la página de cada función.

  • Workflows: estructura de la clase y modelo de orquestación determinista.
  • Actividades: efectos secundarios, reintentos y enrutamiento.
  • Actividades locales: trabajo breve en el mismo proceso con historial de actividad y semántica de reintentos.
  • Señales, Actualizaciones y Consultas: contratos que expone el workflow.
  • Temporizadores, Esperas por condición y Continuar como nueva ejecución: control del flujo de larga duración.
  • Flujos de mensajes: mensajes repetidos y ordenados con semántica de cursor.

Objeto base de workflow

use Workflow\V2\Workflow;

abstract class Workflow
{
    public ?string $connection = null;
    public ?string $queue = null;

    public function workflowId(): string;
    public function runId(): string;
    public function lastChild(): ?ChildWorkflowHandle;
    public function children(): array;
    public function historyLength(): int;
    public function historySize(): int;
    public function shouldContinueAsNew(): bool;
}
MiembroCuándo usarloContrato de retorno
workflowId()El workflow necesita su id público estable de instancia.Cadena con el id de instancia, invariable al continuar como nueva ejecución.
runId()El workflow necesita el id de la ejecución actual.Cadena con el id de la ejecución seleccionada.
lastChild()El workflow necesita enviar una señal al último hijo creado.ChildWorkflowHandle o null.
children()El workflow necesita referencias a los hijos visibles en la secuencia actual de reproducción.Lista de ChildWorkflowHandle.
historyLength()El workflow necesita una señal del presupuesto de historial por cantidad.Número actual de eventos de historial.
historySize()El workflow necesita una señal del presupuesto de historial por bytes.Tamaño aproximado del historial guardado en bytes.
shouldContinueAsNew()El workflow debe rotar antes de encarecer el historial.true cuando los presupuestos de historial configurados recomiendan rotar.

Comandos duraderos​

La fachada estática delega en funciones auxiliares del espacio Workflow\V2. Ambas formas son equivalentes:

use Workflow\V2\Workflow;
use function Workflow\V2\activity;

$resultFromFacade = Workflow::activity(SendReceipt::class, $orderId);
$resultFromHelper = activity(SendReceipt::class, $orderId);

activity() y executeActivity() programan tareas de actividad duraderas en cola. localActivity() y executeLocalActivity() se ejecutan en el proceso actual del worker de workflow y registran historial normal de actividad con el marcador local. Usa sideEffect() para instantáneas seguras para la reproducción que no deban usar reintentos, tiempos de espera, latidos o cancelación de actividades. Usa Workflow::workerSession() o Workflow\V2\workerSession() si varios pasos de actividad ordinarios necesitan el contrato de afinidad de sesión de worker. Consulta el contrato completo en Modelo de ejecución de actividades, Actividades locales y Sesiones de worker.

Funciones auxiliares de temporizadores

Estas funciones son abreviaturas de timer() y Workflow::timer():

use Workflow\V2\Workflow;

Workflow::minutes(5);
Workflow::hours(2);
Workflow::days(1);
Workflow::weeks(1);
Workflow::months(1);
Workflow::years(1);
Función auxiliarEquivalente
seconds(int $seconds)timer($seconds)
minutes(int $minutes)timer($minutes * 60)
hours(int $hours)timer($hours * 3600)

Usa llamadas explícitas a timer() cuando la duración provenga de configuración o de la entrada del workflow. Usa las funciones auxiliares para expresar en el código una espera fija del negocio.

Flujos de mensajes

Abre flujos de mensajes duraderos desde la instancia del workflow:

use Workflow\V2\MessageStream;
use Workflow\V2\Workflow;

final class AssistantWorkflow extends Workflow
{
    public function handle(string $targetWorkflowId): array
    {
        $message = $this->inbox('ai.user')->receiveOne();

        if ($message === null) {
            return ['status' => 'waiting'];
        }

        $reply = $this->outbox('ai.assistant')->sendReference(
            targetInstanceId: $targetWorkflowId,
            payloadReference: 'app://payloads/reply-123',
            correlationId: $this->workflowId(),
            idempotencyKey: 'reply-123',
            metadata: ['kind' => 'assistant_reply'],
        );

        return [
            'status' => 'sent',
            'stream' => $reply->stream_key,
            'sequence' => $reply->sequence,
        ];
    }
}
MétodoFirmaContrato
$this->messages()messages(?string $streamKey = null, ?MessageService $messages = null): MessageStreamAbre el flujo para leer o enviar.
$this->inbox()inbox(?string $streamKey = null, ?MessageService $messages = null): MessageStreamAlias para código de recepción.
$this->outbox()outbox(?string $streamKey = null, ?MessageService $messages = null): MessageStreamAlias para código de envío.
MessageStream::key()key(): stringDevuelve la clave del flujo.
MessageStream::cursor()cursor(): intDevuelve la posición del cursor duradero de esta ejecución.
MessageStream::hasPending()hasPending(): boolIndica si existen mensajes sin consumir.
MessageStream::pendingCount()pendingCount(): intDevuelve la cantidad de mensajes sin consumir.
MessageStream::peek()peek(int $limit = 100): CollectionLee mensajes pendientes sin consumirlos.
MessageStream::receive()receive(int $limit = 1, ?int $consumedBySequence = null): CollectionLee y consume mensajes, registrando el avance del cursor.
MessageStream::receiveOne()receiveOne(?int $consumedBySequence = null): ?WorkflowMessageLee y consume un mensaje.
MessageStream::sendReference()sendReference(string $targetInstanceId, ?string $payloadReference = null, MessageChannel|string $channel = MessageChannel::WorkflowMessage, ?string $correlationId = null, ?string $idempotencyKey = null, array $metadata = [], ?DateTimeInterface $expiresAt = null): WorkflowMessageEnvía a otra instancia un mensaje ordenado con referencia a la carga útil.

Usa flujos de mensajes para mensajes repetidos y ordenados con semántica de cursor. Usa Señales para eventos externos puntuales y Actualizaciones para mutaciones con solicitud y respuesta.

Atributos y contratos públicos

use Workflow\QueryMethod;
use Workflow\UpdateMethod;
use Workflow\V2\Attributes\Signal;
use Workflow\V2\Attributes\Type;
use Workflow\V2\Workflow;

#[Type('order-approval')]
#[Signal('approved-by', [
    ['name' => 'approvedBy', 'type' => 'string', 'allows_null' => false],
])]
final class OrderApprovalWorkflow extends Workflow
{
    private string $stage = 'waiting';

    public function handle(): void
    {
        $this->stage = Workflow::awaitSignal('approved-by');
    }

    #[QueryMethod('current-stage')]
    public function currentStage(): string
    {
        return $this->stage;
    }

    #[UpdateMethod('mark-ready')]
    public function markReady(): string
    {
        return $this->stage = 'ready';
    }
}
AtributoDestinoContrato estable
#[Type('type-key')]Clase de workflow o actividadDeclara la clave de tipo duradera independiente del lenguaje.
#[Signal('signal-name', [...])]Clase de workflow, repetibleDeclara los nombres de señal aceptados y contratos opcionales de parámetros ordenados.
#[QueryMethod('query-name')]Método de workflowDeclara un nombre de consulta seguro para la reproducción. Omítelo para usar el nombre del método PHP.
#[UpdateMethod('update-name')]Método de workflowDeclara un nombre de actualización seguro para la reproducción. Omítelo para usar el nombre del método PHP.

Las señales, consultas y actualizaciones son contratos públicos. Prefiere nombres explícitos para que renombrar métodos PHP no rompa la API.

Superficie de fallos

Los fallos de la API de autoría son fallos duraderos del workflow, salvo que el comando se rechace antes de ejecutarse:

SuperficieFallo habitualSignificado para el operador
activity()La actividad lanza una excepción, vence su plazo o agota los reintentos.La ejecución registra el fallo de actividad en el historial y sigue el manejo de errores del workflow.
child()El hijo falla, se cancela, termina o agota su plazo.El padre observa un resultado de fallo del hijo en el comando que espera.
await()Vence el plazo antes de satisfacerse la condición o señal.La espera devuelve un valor o falla según la forma elegida.
timer()La duración normalizada no es válida.El código debe pasar duraciones positivas o esperas explícitas de duración cero.
continueAsNew()No se puede crear la nueva ejecución.La ejecución actual conserva la evidencia de la transición fallida.
upsertSearchAttributes()La clave, cantidad o tamaño total de atributos supera los límites.La ejecución falla antes de guardar metadatos indexados no válidos.
MessageStream::receive()No hay una secuencia positiva de historial disponible.La recepción debe ocurrir durante la ejecución del workflow, no desde código directo de servicio.
MessageStream::sendReference()La referencia de carga, ruta o contrato de almacenamiento no es válido en el destino.El orden de mensajes es independiente de la integridad del almacén de cargas útiles.

Consulta los límites de cargas e historial en Límites estructurales. Para respuestas de rechazo de comandos fuera del código PHP del workflow, consulta Referencia de la API del servidor.

Reglas de determinismo

El código del workflow debe ser seguro para la reproducción. Encapsula el trabajo irreversible o no determinista en comandos duraderos:

use Workflow\V2\Workflow;

final class DeterministicWorkflow extends Workflow
{
    public function handle(): array
    {
        $workflowTime = Workflow::now();
        $stableId = Workflow::uuid7();
        $remoteQuote = Workflow::activity(FetchQuote::class);

        return [
            'time' => $workflowTime->toIso8601String(),
            'id' => $stableId,
            'quote' => $remoteQuote,
        ];
    }
}
  • Usa Workflow::now() en lugar del reloj real en las bifurcaciones del workflow.
  • Usa Workflow::uuid4() o Workflow::uuid7() en lugar de aleatoriedad directa.
  • Coloca las llamadas de red, escrituras de archivos, envíos de correo y efectos secundarios externos en actividades.
  • Usa Workflow::sideEffect() solo si el valor debe capturarse en el historial y el efecto en sí no es la acción de negocio.
  • Usa Workflow::getVersion(), Workflow::patched() y Workflow::deprecatePatch() para evolucionar el código sin romper la reproducción.
