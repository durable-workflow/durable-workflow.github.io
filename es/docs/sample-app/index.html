Aplicación de ejemplo

https://github.com/durable-workflow/sample-app

Esta es la galería de Laravel integrado: una aplicación Laravel 13 de ejemplo basada en la línea estable Durable Workflow 2.0, con workflows ejecutables en un GitHub Codespace. Es el punto de partida adecuado si tu modelo de despliegue es Laravel integrado y quieres examinar juntos la ejecución de colas de Laravel y Waterline.

Elige los ejemplos que correspondan a tu entorno de ejecución:

Modelo de despliegueEjemplos que debes usar
Durable Workflow CloudEmpieza con Entorno de ejecución gestionado de Cloud y después elige la guía del SDK PHP, Python o Rust con las credenciales del namespace provisionado. Los usuarios de Cloud no ejecutan Server.
Modo servicio autogestionadoUsa el inicio rápido de Durable Workflow 2.0 para obtener ejemplos completos con artefactos publicados de PHP, Python y Rust contra un Server local.
Laravel integradoContinúa con esta galería y la instalación integrada.

La galería aporta evidencia de principio a fin del motor alojado en Laravel. No es una aplicación inicial universal para despliegues en modo servicio o políglotas. Es el primer lugar donde las funcionalidades integradas reciben cobertura realista de Laravel, y la fuente que refleja este sitio cuando muestra un patrón nativo de Laravel. Si quieres compartir un patrón de Durable Workflow, la guía Aportar un ejemplo explica el proceso de envío.

¿Buscas la versión de Laravel 12 / Durable Workflow 1.x? Se conserva en la rama Laravel-12. Los artículos y tutoriales antiguos que usan patrones de v1 (por ejemplo, Workflow\Workflow, yield activity(...), Workflow\Activity) corresponden a esa rama.

Cada entrada identifica el patrón que enseña, la clase de workflow que lo ejercita, el comando Artisan que lo ejecuta y la pantalla de Waterline que demuestra que la ejecución se confirmó. La galería refleja «Sample Index» del README del repositorio sample-app. Cuando se añade o mueve un ejemplo, el README y esta galería se actualizan juntos.

Paso 1

Crea un codespace a partir de la rama main de este repositorio.

Paso 2

Espera a que termine la preparación del codespace. Debería tardar entre 5 y 10 minutos.

Paso 3

Al terminar verás el editor y el terminal en la parte inferior.

Paso 4

Ejecuta composer install.

composer install

Paso 5

Ejecuta el comando de inicialización para configurar la aplicación, instalar dependencias adicionales y ejecutar las migraciones.

php artisan app:init

La ruta php artisan migrate de la aplicación de ejemplo carga directamente las migraciones de los paquetes Workflow y Waterline. Todas las tablas y vistas guardadas de Waterline quedan listas tras la instalación normal.

Paso 6

Inicia el worker de colas para procesar workflows y actividades.

php artisan queue:work

Para comprobar el propio ciclo de reparación sin esperar a que un worker ocupado llegue a otro ciclo Looping, ejecuta una pasada explícita de recuperación desde un segundo terminal:

php artisan workflow:v2:repair-pass

Este comando usa la misma exploración y política de espera progresiva que el bucle del worker. Resulta útil tras corregir un problema local de cola o backend, al validar una tarea perdida en la aplicación de ejemplo o cuando un codespace con poco tráfico tardaría en realizar otra pasada. Añade --run-id=... para limitarla a una o más ejecuciones seleccionadas durante un experimento, o --instance-id=... para abarcar toda la instancia.

Paso 7

Crea una ventana de terminal nueva.

Paso 8

Inicia el workflow de ejemplo en el terminal nuevo.

php artisan app:workflow

Paso 9

Puedes abrir el panel de Waterline en https://[your-codespace-name]-80.preview.app.github.dev/waterline/dashboard.

Waterline muestra el estado duradero. Permite ver si un workflow arrancó, qué ejecución es la actual, qué eventos tipados se confirmaron, qué esperas están abiertas y qué acciones de operador hay disponibles. La telemetría del worker es independiente: la latencia de sondeo, duración de tareas, configuración de exportadores, métricas personalizadas y errores del proceso proceden de los registros del worker PHP o del endpoint de métricas del SDK de un worker externo.

InterfazQué permite conocerComprobación de ejemplo
Waterline y exportación del historialEstado duradero del workflow, historial, reintentos, esperas, señales, actualizaciones, fallos y acciones de operadorAbre /waterline/dashboard y exporta el historial de la ejecución seleccionada
Registros del workerErrores del proceso del worker de colas PHP y líneas del registro de la aplicaciónSigue storage/logs/laravel.log mientras se ejecuta php artisan queue:work
Métricas del SDKRecuentos de peticiones del worker/cliente externo, latencia de sondeo y duración de tareasRecoge el endpoint Prometheus/OpenMetrics del worker del SDK

Para un worker Python, instala el extra de Prometheus y expón las métricas desde el propio proceso:

pip install 'durable-workflow[prometheus]'
from prometheus_client import start_http_server

from durable_workflow import Client, PrometheusMetrics, Worker

metrics = PrometheusMetrics()
start_http_server(9102)

async with Client("http://localhost:8080", token="secret", metrics=metrics) as client:
    worker = Worker(
        client,
        task_queue="default",
        workflows=[GreeterWorkflow],
        activities=[greet],
        metrics=metrics,
    )
    await worker.run()

Sustituye GreeterWorkflow y greet por los manejadores de workflow y actividad registrados en ese worker.

Recoge :9102/metrics para obtener las series durable_workflow_worker_* y durable_workflow_client_*. Estas métricas explican el rendimiento del worker. Waterline sigue siendo la referencia para el historial de workflow confirmado.

La pantalla de detalle de Waterline incluye la acción «Export History» para la ejecución seleccionada. Si muestra la ejecución actual de la instancia, usa la ruta de exportación de ejecución actual de la instancia. El detalle de una ejecución histórica sigue usando la ruta explícita /runs/{runId}/history-export. También puedes exportar el mismo paquete de reproducción y depuración desde el terminal:

php artisan workflow:v2:history-export {workflow-instance-id} --run-id={workflow-run-id} --output=storage/app/workflow-history/example.json --pretty

La exportación incluye una suma de integridad SHA-256. Configura DW_V2_HISTORY_EXPORT_SIGNING_KEY y DW_V2_HISTORY_EXPORT_SIGNING_KEY_ID en el entorno de la aplicación si otro sistema necesita verificar el paquete con una firma HMAC.

El bloque selected_run exportado incluye waits_projection_source, timeline_projection_source, timers_projection_source y lineage_projection_source. El bloque links incluye además projection_source. Las secciones links.parents / links.children proceden primero del historial tipado de relaciones de la ejecución seleccionada, por lo que las relaciones de workflows hijos y continue-as-new siguen visibles aunque las filas de enlaces mutables se hayan desviado en un experimento local. Cuando una relación solo sobrevive en datos antiguos de compatibilidad mutables, el paquete la marca con history_authority = mutable_open_fallback y diagnostic_only = true, en vez de rehidratar silenciosamente metadatos adicionales al exportar.

Flujos de mensajes de workflows de IA​

Los workflows repetidos de IA o entrada humana deben usar la fachada de flujos de mensajes v2 como patrón de creación:

$reply = $this->inbox('ai.assistant')->receiveOne();

$this->outbox('ai.assistant')->sendReference(
    targetInstanceId: $this->workflowId(),
    payloadReference: $storedReplyReference,
    correlationId: $requestId,
);

Mantén el almacenamiento de cargas grandes de petición/respuesta en la aplicación y pasa la referencia almacenada por el flujo. Los ejemplos nuevos no deben enseñar a escribir directamente workflow_messages, MessageStreamCursor ni llamadas a MessageService. Consulta Flujos de mensajes para ver el contrato estable de inbox/outbox v2.

Paso 10

Ejecuta las pruebas de workflows y actividades.

vendor/bin/phpunit

Ya puedes crear y probar workflows.

Servidor MCP para clientes de IA​

La aplicación también expone un servidor MCP de Laravel en /mcp/workflows. Es la interfaz de referencia para clientes de IA de Durable Workflow v2: ofrece a los agentes descubrimiento estructurado de workflows, inicio, estado, salida, historial tipado reciente y datos de fallos sin extraer información de las páginas de Waterline.

Para el contrato detallado del endpoint y las herramientas MCP, consulta Interfaz de workflows MCP. Para el contrato general de desarrollo asistido por IA, incluidos los manifiestos LLM de v2, códigos de salida de CLI, exportaciones de Waterline y referencias de SDK, consulta Desarrollo asistido por IA.

El paquete Laravel MCP registra el servidor desde routes/ai.php. Las claves de workflow expuestas están en config/workflow_mcp.php. Cada entrada puede incluir la clase y metadatos de descubrimiento, como descripción, requisitos de credenciales y argumentos esperados.

Herramientas predeterminadas:

HerramientaFunción
list_workflowsEnumera las claves de workflow configuradas, requisitos de credenciales, estados de v2 y, opcionalmente, ejecuciones recientes.
start_workflowInicia un workflow v2 configurado y devuelve workflow_id, run_id, estado, clave de negocio y resultado del comando.
get_workflow_resultSondea la ejecución actual o seleccionada y devuelve estado, salida, metadatos de visibilidad y resumen del último fallo.
get_workflow_historyDevuelve un tramo final acotado de eventos tipados del historial v2 y los últimos fallos duraderos para depuración.
diagnose_workflowClasifica una ejecución seleccionada con datos estructurados, causa raíz, solución y siguientes acciones.
repair_workflowSolicita el comando de reparación integrado de v2 y devuelve un resultado de mutación estructurado: aceptado, rechazado o innecesario.

Un ciclo habitual de agente es:

{"tool": "list_workflows", "arguments": {"show_recent": true, "limit": 5}}
{"tool": "start_workflow", "arguments": {"workflow": "simple", "business_key": "demo-001"}}
{"tool": "get_workflow_result", "arguments": {"workflow_id": "<workflow_id>"}}
{"tool": "get_workflow_history", "arguments": {"run_id": "<run_id>", "limit": 25}}

Usa simple o elapsed para comprobaciones básicas sin credenciales. El workflow prism se expone como ejemplo de IA, pero requiere OPENAI_API_KEY para que un worker pueda completarlo.
