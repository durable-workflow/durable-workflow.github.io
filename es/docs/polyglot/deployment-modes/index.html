Modos de despliegue

Servicio gestionado · grupo limitado

Grupo de lanzamiento de Durable Workflow Cloud

Elige el servicio gestionado para tus workers de PHP, Python o Rust sin operar el entorno de orquestación.

Solicita acceso anticipado

Durable Workflow v2 tiene dos modos de despliegue:

  • Modo servicio: las aplicaciones y los workers se conectan mediante SDK a un entorno remoto. Elige Cloud o Server autogestionado.
  • Modo integrado: una aplicación Laravel instala durable-workflow/workflow y opera directamente el entorno.

Cloud y Server autogestionado son alternativas dentro del modo servicio. Cloud opera la orquestación, la persistencia y Managed Waterline. El cliente ejecuta sus aplicaciones y workers. En Cloud no instalas ni despliegas tu propio Server ni un servicio Waterline separado. Server autogestionado no incluye Waterline. Puedes desplegarlo por separado para observar un espacio de nombres gestionado por Server.

Usa esta página para elegir quién mantiene tus workflows o planificar un cambio de modelo. Los equipos Laravel pueden consultar la Guía de adopción y transición, incluido el puente Laravel del SDK PHP y su implementación de pruebas.

El mismo modelo duradero con distintas interfaces​

Los dos modos comparten el núcleo de v2. Cambian el alojamiento, la autenticación y el transporte. El modo servicio expone HTTP+JSON, sin gRPC obligatorio ni un segundo motor.

Cuándo elegir el modo integrado​

  • Tu aplicación Laravel reúne código, workers y acceso de operadores.
  • Sus colas y su autenticación son la interfaz adecuada.
  • Quieres un entorno autocontenido y no necesitas workers de otros lenguajes.
  • Tus operadores pueden usar Waterline integrado o las herramientas de la aplicación.

Empieza con Instalación integrada y la Documentación del modo integrado.

Cuándo elegir el modo servicio​

  • Varias aplicaciones o equipos comparten un entorno de workflows.
  • Los workers, clientes u operadores no usan todos Laravel/PHP.
  • Necesitas autenticación remota y espacios de nombres explícitos.
  • Quieres escalar por separado las API, el despacho y los workers mediante la Topología de roles de Server.
  • Quieres observar Server autogestionado con un Waterline separado. Cloud ya incluye Managed Waterline.

Para el servicio gestionado, empieza con Cloud. Para autogestión, consulta Server y Despliegues autogestionados. Elige después el SDK PHP, SDK Python o SDK Rust. Para un Waterline separado, consulta la API de Server y Monitorización.

Transición al modo servicio autogestionado​

La ruta admitida es una adopción gradual:

  • Sigue Migración del modo integrado a Server.
  • Comprueba la versión, topología y capacidades con GET /api/cluster/info.
  • Registra workers con POST /api/worker/register y verifica que ejecutan los nombres de tipos estables elegidos.
  • Antes de cambiar el tráfico, comprueba la cobertura de workers compatibles mediante GET /api/system/operator-metrics, dw worker:list o Waterline.
  • Consulta Capacidades de clientes y workers al sustituir llamadas locales por automatización remota.
  • Usa Waterline o la exportación del historial para auditoría y diagnóstico. Una exportación no importa ejecuciones activas en otro entorno.

Respeta estas tres reglas:

  1. Las ejecuciones existentes permanecen donde empezaron.
  2. Las nuevas usan nombres estables de tipos, espacios de nombres, colas y el contrato Avro desde el primer cambio de tráfico.
  3. Señales, consultas, actualizaciones, reparación, cancelación, terminación y archivo se dirigen al entorno que posee la ejecución.
