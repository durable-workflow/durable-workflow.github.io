Índice de capacidades de Durable Workflow 2.0

Este es el índice de capacidades de la línea estable Durable Workflow 2.0.

Canal instalable admitido​

Las identidades exactas de los artefactos corresponden a los registros de paquetes y a los metadatos de publicación, no a este resumen de capacidades.

InterfazCanal admitidoFunción en este índice
CLI2.0 estableCliente de operador y diagnóstico con salida legible por máquina.
SDK de PHP2.0 estableCliente oficial durable-workflow/sdk en modo servicio y worker remoto de workflows y actividades para el runtime de un namespace de Cloud o un Server autogestionado.
Motor Laravel integrado2.0 estableModo de despliegue separado dentro de la aplicación mediante durable-workflow/workflow, con su propio runtime de autoría, motor de persistencia, colas y reproducción.
SDK de Python2.0 estableSDK oficial determinista de workflows y actividades en modo servicio, más cliente operativo y del plano de control para el runtime de un namespace de Cloud o un Server autogestionado. Requiere Python 3.10 o posterior.
SDK de Rust2.0 estableSDK oficial determinista de workflows y actividades en modo servicio, servicio de workers y cliente del plano de control para el runtime de un namespace de Cloud o un Server autogestionado. Requiere Rust 1.86 o posterior.
Server2.0 estableRuntime autogestionado, implementado en PHP e independiente del lenguaje, para los protocolos v2 del plano de control y de workers.
Waterline2.0 estableCloud incluye Managed Waterline. Los operadores autogestionados despliegan por separado la imagen del servicio contra un namespace de Server. Laravel integrado instala el paquete Composer y lee en el mismo proceso el estado que pertenece a la aplicación.

PHP, Python y Rust son los tres lenguajes con SDK oficiales en modo servicio. Todos pueden dirigirse al runtime de un namespace provisionado de Durable Workflow Cloud o a un Server autogestionado cuyo descubrimiento anuncie la capacidad publicada. Comparten nombres de tipo estables de cadena, un modelo de comandos e historial duradero, versión 2 del plano de control, versión mayor 1 del protocolo de workers y el sobre público de cargas útiles. Rust es un SDK de workflows: ejecuta código determinista de workflow, actividades y servicios de workers, además de llamadas de protocolo de bajo nivel. Python combina la autoría de workflows con interfaces de cliente para namespaces, programaciones, workers, colas, historial, reparación y otras operaciones.

Laravel integrado sigue siendo un modo de despliegue PHP separado dentro de la aplicación. No es necesario para los clientes ni los workers PHP en modo servicio. El SDK de PHP independiente del framework se versiona por separado del motor Laravel integrado.

Usa Modos de despliegue para elegir el límite de responsabilidades y continúa con Entorno gestionado de Cloud o con Server autogestionado. La evidencia de capacidades que sigue solo se aplica si el runtime elegido anuncia el contrato necesario.

El SDK de PHP 2.3.2, el SDK de Python 2.5.7 y el SDK de Rust 3.5.0 usan por defecto el protocolo de workers 1.20. Los workers predeterminados necesitan un Server que anuncie 1.20 o posterior dentro de la versión mayor 1. Cada SDK también permite seleccionar explícitamente 1.19 para un Server anterior compatible. La cancelación cooperativa requiere 1.20 y habilitar explícitamente su capacidad. El descubrimiento del runtime y los metadatos publicados del SDK elegido determinan la compatibilidad. Consulta Compatibilidad de versiones y Protocolo de workers.

Capacidades y versiones mínimas de SDK​

«Modo servicio» significa que Cloud o un Server autogestionado opera el runtime remoto. «Integrado» significa que una aplicación Laravel opera el runtime en su propio proceso. La columna de SDK registra las diferencias deliberadamente. Una entrada vacía o un SDK limitado no implica paridad.

CapacidadContrato actual de 2.0 y versión mínima oficialEvidencia explícita de 2.0
WorkflowsLos workers remotos PHP, Python y Rust permiten escribir workflows deterministas. La autoría en Laravel integrado usa el paquete Workflow.Autoría de workflows, SDK de PHP, SDK de Python, SDK de Rust
Actividades y serviciosEl motor integrado y los tres SDK en modo servicio permiten escribir actividades. Los workflows y actividades Rust se ejecutan en servicios de workers oficiales. Python y PHP también ofrecen clientes oficiales de control y servicio.Actividades, SDK de PHP, Ejecución de actividades, Ejecución externa
Llamadas de servicio entre espacios de nombresPHP integrado, PHP SDK y Python SDK crean operaciones de servicio duraderas registradas con espera de finalización o solo admisión y resultados registrados. El espacio de destino en PHP servicio usa actualmente la opción de array namespace. Las llamadas de autoría Rust no están disponibles hasta sdk-rust #86.Autoría integrada, Catálogo compartido y soporte de SDK
SeñalesLas interfaces de workflow de PHP, Python y Rust ofrecen modificaciones duraderas y asíncronas en sus versiones mínimas actuales.Señales, SDK de Python, SDK de Rust
ConsultasSe admiten consultas de solo lectura mediante reproducción. PHP, Python y Rust ofrecen manejadores y clientes de consultas. Las tareas de consulta reproducidas de Rust requieren el protocolo de workers 1.8 o posterior.Consultas, SDK de Python, SDK de Rust
ActualizacionesPHP, Python y Rust ofrecen interfaces de cliente y manejadores de worker para actualizaciones. Los validadores declarados de Python utilizan validación síncrona previa a la aceptación cuando el descubrimiento de Server anuncia ese contrato exacto: la aceptación sigue a la aprobación, mientras que el rechazo, la pérdida del worker, el tiempo de espera agotado y una finalización sin autoridad válida fallan explícitamente. PHP y Rust no ofrecen autoría de validadores y no declaran ninguno.Actualizaciones, SDK de Python, SDK de Rust
TemporizadoresLos temporizadores duraderos respaldados por el runtime del servicio se reproducen en PHP, Python y Rust.Temporizadores, SDK de Rust
ReintentosLa política duradera de reintentos de actividades se registra con el comando. PHP, Python y Rust ofrecen opciones de reintento de actividades en sus versiones mínimas actuales.Fallos y recuperación, SDK de Python, SDK de Rust
Tiempos de esperaLos runtimes en modo servicio de Cloud y Server autogestionado aplican las familias de tiempos de espera de actividades y workflows. Rust incluye opciones de actividad y plazos de ejecución y de inicio de ejecución de workflows.Tiempos de espera, SDK de Rust
Workflows hijosPHP, Python y Rust inician y esperan hijos duraderos. La identidad de tipo entre lenguajes es una cadena estable y las cargas útiles de los hijos usan el sobre compartido.Workflows hijos, SDK de Python
Composición paralela deterministaall()/parallel() de PHP, list-yield anidado de Python y WorkflowContext::parallel()/join() de Rust programan grupos de actividades, workflows hijos, temporizadores, grupos mixtos y anidados mediante comandos ordinarios. Los tres publican metadatos compartidos de identidad y ruta del grupo, y restauran los resultados en el orden de las entradas anidadas.Concurrencia, SDK de Python, SDK de Rust
Selección duradera de la primera finalizaciónPHP integrado y los SDK de servicio de PHP, Python y Rust inician miembros independientes de actividad, workflow hijo, temporizador, espera de entrada externa y grupos anidados. Se persiste un ganador con identidad estable de miembro. Los demás continúan y conservan handles para esperar o cancelar.Concurrencia, SDK de Python, SDK de Rust
Compensación de sagasLos helpers Saga de PHP, WorkflowContext.saga() de Python y WorkflowContext::saga() de Rust registran compensaciones duraderas después del éxito de la operación hacia delante y las ejecutan secuencialmente en orden inverso por defecto. Python y Rust se detienen en el primer fallo de compensación y conservan tanto el fallo inicial como el de compensación. PHP también ofrece políticas opcionales de ejecución paralela y continuación tras errores.Sagas, SDK de Python, SDK de Rust
CancelaciónLaravel integrado y PHP, Python y Rust en modo servicio admiten solicitudes cooperativas de cancelación con una identidad raíz, un plazo inmutable y limpieza acotada en workers que las habilitan explícitamente. La cancelación terminal inmediata sigue disponible con seguridad sobre la ejecución seleccionada y resultados con tipos definidos.Cancelar y terminar, Cancelación en modo servicio, SDK de Rust
TerminaciónTerminar cierra una ejecución inmediatamente con un resultado terminal propio. Está disponible mediante los runtimes de servicio de Cloud y Server autogestionado y las interfaces de control de CLI, PHP, Python y Rust.Cancelar y terminar, API de Server
Side effectsPHP, Python y Rust registran valores no deterministas exactamente una vez y decodifican el valor registrado durante la reproducción.Side effects, SDK de Python, SDK de Rust
Workflow StreamsPHP, Python y Rust ofrecen operaciones tipadas para listar, describir, suscribirse o reanudar por posición, añadir, cerrar y marcar errores en flujos de salida asociados a una ejecución y gestionados por Server. Los tres permiten emitir de forma segura para la reproducción a partir de una identidad de comando duradera. Python resuelve cargas útiles externas con su controlador de almacenamiento configurado. PHP y Rust conservan referencias opacas.Workflow Streams, Matriz exacta de SDK, Escenarios de runtime
Marcadores de versiónPHP, Python y Rust ofrecen marcadores duraderos de versión para evolucionar el código de forma compatible.Versionado, SDK de Python, SDK de Rust
Reproducción deterministaLos workers de workflow de PHP, Python y Rust reconstruyen decisiones a partir del historial duradero e informan del no determinismo con tipos definidos, sin volver a ejecutar trabajo externo.Garantías de ejecución, Conformidad de la plataforma, SDK de Rust
ProgramacionesLos runtimes de servicio de Cloud y Server autogestionado gestionan programaciones duraderas. PHP, Python y CLI ofrecen operaciones de programación. Rust no ofrece una API de gestión de programaciones.Programaciones, Referencia del CLI, SDK de Python
NamespacesLos runtimes en modo servicio están limitados por namespace. Los clientes PHP/Python y el CLI gestionan namespaces cuando el runtime elegido expone esa operación. Los workers y clientes Rust se dirigen a un namespace, pero no ofrecen administración de namespaces en la versión mínima actual.Namespaces, autenticación y workers, API de Server
Atributos de búsquedaLos runtimes de servicio de Cloud y Server autogestionado indexan atributos de búsqueda tipados. PHP y Python ofrecen interfaces de autoría y control. El CLI y las API de operador ofrecen descubrimiento y filtrado estructurados.Atributos de búsqueda, SDK de Python
Compatibilidad de workersLos SDK registran runtime, versión del SDK, ID de compilación, tipos admitidos, versión del protocolo y capacidad. El servidor publica las versiones aceptadas y los hechos de enrutamiento.Compatibilidad, Compatibilidad y enrutamiento de workers
Actividades localesDisponibles en Laravel integrado, los SDK de servicio PHP y Python y el SDK de Rust 3.1.0, con habilitación explícita del worker.Ejecución de actividades integradas, Matriz de compatibilidad en modo servicio
Sesiones de workersDisponibles en Laravel integrado, los SDK de servicio PHP y Python y el SDK de Rust 3.2.0, con habilitación explícita del worker.Sesiones de workers, Matriz de compatibilidad en modo servicio
Ejecución stickyDisponible en Laravel integrado y en el SDK de servicio PHP. Python y Rust también ofrecen cachés de historial opcionales y acotadas que deben habilitarse explícitamente en el worker. Todos los workers deben seguir reproduciendo correctamente desde cero.Ejecución sticky, Matriz de compatibilidad en modo servicio
Interoperabilidad de códecsPHP, Python y Rust usan el sobre público codec + blob y un único esquema recursivo fijo Avro Value. Las ramas con nombre preservan enteros frente a doubles, texto frente a bytes, booleanos frente a enteros y listas frente a mapas.Protocolo Avro Value, Protocolo de workers, SDK de Rust
DiagnósticosLos runtimes de servicio y el CLI publican en JSON hechos sobre versión, protocolo, workers, colas de tareas, reproducción, historial, fallos con tipos definidos y reparación. Managed Waterline, un servicio autogestionado desplegado por separado o el paquete integrado presentan evidencia del runtime correspondiente.Monitorización, Referencia del CLI, API de operador de Waterline
Herramientas de agentesEl ciclo Descubrir -> Cambiar -> Ejecutar -> Diagnosticar -> Reparar está disponible mediante manifiestos públicos, esquemas, operaciones HTTP, JSON del CLI, clientes SDK, historial y diagnósticos con tipos definidos y modificaciones seguras. MCP es una interfaz opcional, no la definición del contrato.Contrato de herramientas para agentes, Ciclo operativo de agentes

Límite de interoperabilidad de cargas útiles​

Las llamadas a workflows y actividades entre lenguajes no pasan objetos PHP serializados, pickles de Python ni tipos de implementación Rust. Pasan nombres de tipo de cadena registrados y un sobre público de cargas útiles. Con avro, cada SDK oficial utiliza la implementación oficial de su lenguaje y el mismo esquema fijo Value. Los mapas, listas, cadenas, bytes, enteros, doubles, booleanos y nulos decodificados conservan su tipo primitivo. Las clases específicas de un lenguaje solo se reconstruyen dentro de su propio SDK.

Este contrato se aplica a entradas y resultados de workflow, workflows hijos, entradas y resultados de actividad, señales, consultas, actualizaciones y ejecución externa. Los despliegues deben verificar los códecs anunciados por GET /api/cluster/info antes de admitir un worker.
