サポート

Durable Workflow はオープンソースプロジェクトであり、MIT ライセンスの下で無料で使用できます。実行、配布、本番システムの構築に商用契約は必要ありません。

コミュニティサポート​

Durable Workflow の支援を得る主な方法はコミュニティです。公開の質問、設計の議論、バグ報告、運用パターンの共有に適しています。

次のような内容に最適です。

  • 使い方の質問
  • ワークフローのモデル化に関する助言
  • 決定性とリプレイを理解するための支援
  • アイデアやパターンの共有
  • バグや予期しない動作の報告

GitHub Discussions​

詳しい質問、設計の議論、他の利用者にも役立つ問題には、GitHub Discussions を推奨します。

https://github.com/durable-workflow/workflow/discussions

Discord​

Discord は次に適しています。

  • 簡単な質問
  • 気軽な議論
  • 初期のフィードバック
  • コミュニティでの協力

https://discord.gg/xu5aDDpqVy

コミュニティサポートは可能な範囲で提供され、開発、実験、多くの本番用途には十分な場合があります。

デプロイサポートの境界​

Durable Workflow は、営業相談なしでも役立つよう設計されています。公開ディストリビューションは、多くのチームが最初に必要とする次のデプロイ経路に意図的に最適化しています。

  • ローカル開発と社内の非本番環境 パッケージまたはスタンドアロンサーバーをローカル、LAN、共有ステージング環境で実行し、開発者がワークフローを試して素早く反復できます。
  • 単一ノードの本番環境 永続データベース、キャッシュ、リバースプロキシ、バックアップ、ロールに限定した認証情報を備えた一つの VM、VPS、社内ホストで、スタンドアロンサーバーを実行します。
  • 小規模クラスターデプロイ 共有の外部 MySQL または PostgreSQL、共有 Redis、独立してスケールする Worker、厳密に一つのスケジューラーまたはメンテナンスランナーを使い、ロードバランサーの背後で 2～3 個のステートレス API コンテナを実行します。
  • Kubernetes マニフェスト 既に Kubernetes を運用し、Kubernetes ネイティブな出発点が欲しいチーム向けに、提供マニフェストを使用します。

ホステッドの Durable Workflow Cloud は、別のマネージドオーケストレーションサービスです。Cloud はランタイム、永続化、単一リージョン内の配置、復旧を運用し、顧客は SDK クライアントと Worker を実行します。セルフホストの Server を Cloud に接続することはありません。マルチリージョン複製、リージョンフェイルオーバー、フェイルバックは現在の Cloud 契約に含まれません。

公開ディストリビューションは、ローカル開発、単一ノード本番環境、セルフホストガイドで説明する限定的な小規模クラスター契約に最適化しています。Kubernetes マニフェストは、既に Kubernetes を運用しているチーム向けです。小規模クラスター契約は、ローリングアップグレードのページにあるすべての保証条件を満たす場合に対応します。運用者がリージョンフェイルオーバーを行うアクティブ/パッシブのマルチリージョンは、引き続きサポート主導の評価用ガイダンスです。セルフホストガイドのアクティブ/パッシブのマルチリージョンを参照してください。公開 Helm チャートは、セルフサービスのパッケージ化とロールアウト経路です。カスタムチャート変更、プロバイダーインフラ、重複スケジューラー、Redis なしのマルチノード運用、プロバイダーフェイルオーバー、アクティブ/パッシブまたはアクティブ/アクティブのマルチリージョン、セルフホストの自動リージョンフェイルオーバー、高度な HA トポロジーは、環境固有のサイジング、データベース、ネットワーク、セキュリティ、アップグレードの判断を要するため、引き続きサポート主導です。

具体的なサポートマトリクス、公開イメージを使う Compose 手順、生の Kubernetes マニフェストの境界、準備状態の確認、サポート主導作業の開始点については、セルフホストのデプロイガイドを参照してください。

この境界によりセルフサービスの経路を単純に保ち、デプロイ自体が分散システムのプロジェクトになる場合には、より深い支援を提供できます。

商用サポート（任意）​

追加の安心やメンテナーレベルの専門知識が必要なチームには、商用サポートとコンサルティングを提供しています。

Durable Workflow の利用に商用契約は不要です。商用サポートの利用有無にかかわらず、すべての機能は完全なオープンソースのままです。

商用サポートは、正しさ、アップグレードの安全性、デプロイトポロジー、長期実行の意味が重要な本番システムで Durable Workflow を実行するチーム向けです。

商用サポートの対象​

商用サポートはプロジェクトメンテナーが担当し、通常は次を含みます。

  • 本番デプロイの計画 単一ノード、限定的な小規模クラスター、Kubernetes、サポート主導のデプロイモデルの選択を支援します。データベース、キャッシュ、リバースプロキシ、スケジューラー、Worker の構成も対象です。
  • サイジング、信頼性、アップグレードの計画 容量の前提、バックアップ・復元戦略、初期構築とマイグレーションの順序、ロールアウトの安全性、運用手順書を支援します。
  • 高度なトポロジーのサポート Helm チャートのカスタム変更、プロバイダー固有 Kubernetes インフラ、カスタムオーバーレイ、重複スケジューラー設計、Redis なしのマルチノード、高可用性構成、アクティブ/パッシブ・アクティブ/アクティブのマルチリージョン、セルフホストの自動リージョンフェイルオーバー、同期リージョン間複製の設計を、サポート主導で行います。公開チャートはセルフサービスのインストール経路です。セルフホストガイドは、サポート主導の評価向けにアクティブ/パッシブの構成と手順を保持しています。別の Cloud マネージドランタイム契約は、ホステッドサービスの単一リージョン配置、復旧、接続の境界を文書化しています。
  • セキュリティレビュー ロールに限定した認証情報、ネットワーク公開範囲、内部・公開エンドポイント、TLS 終端、運用者と Worker のアクセス境界を支援します。
  • ワークフローのアーキテクチャと設計レビュー アクティビティ境界、シグナル、inbox/outbox の使用、長期実行パターンを含む、正しいワークフローのモデル化を支援します。
  • 決定性とリプレイの安全性 非決定的な動作、リプレイの問題、時間の経過で表面化する微妙な正しさの問題の特定と回避を支援します。
  • アップグレードとバージョン管理の戦略 安全なアップグレード、ワークフローのバージョン管理、continue-as-new などのパターンが必要になる時点の判断を支援します。
  • 複雑なワークフロー動作のデバッグ 停止したワークフロー、予期しないループ、シグナル処理の問題、その他理解の難しいランタイム動作を診断します。
  • バックポートとパッチ プライベートフォークの保守を避けられるよう、サポート対象バージョンの修正とバックポートを提供します。
  • カスタム連携（要相談） チャットプラットフォーム、承認システム、社内 API、可観測性ツールなど、既存システムとの連携を支援します。

商用サポートが適するチーム​

通常、次の場合に適しています。

  • Durable Workflow を本番環境で実行している
  • 複数のチームやサービス向けにスタンドアロンサーバーをデプロイしている
  • 長期実行や人間が関与するワークフローを構築している
  • 実証済みの単一リージョン 2.0 運用範囲を超える、クラスター、プロバイダー固有またはカスタムの Kubernetes/Helm、アクティブ/パッシブ・アクティブ/アクティブのマルチリージョン、セルフホストの自動フェイルオーバー構成を設計している
  • 正しさとアップグレードの安全性が重要な環境を運用している
  • 一般的なコンサルティングではなく、メンテナーレベルの専門知識を求めている
  • フォークと長期保守のリスクを避けたい
