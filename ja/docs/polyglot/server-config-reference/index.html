Server 設定リファレンス

このページは Durable Workflow Server イメージの運用者向け DW_* 環境変数の契約を説明します。デプロイ用テンプレートの作成、本番設定の確認、従来の WORKFLOW_* / ACTIVITY_* 名から v2 Server の契約への移行に使用してください。

Server は DB_*、REDIS_*、QUEUE_CONNECTION、CACHE_STORE など、通常の Laravel 実行時設定も使用します。これらは Durable Workflow API の設定ではなくデプロイ基盤の設定なので、別の表に記載しています。

変更が反映されるタイミング​

公開済みの PHP Server イメージは、エントリーポイントで php artisan config:cache を実行します。環境変数はその起動時に解決され、Laravel の設定キャッシュに書き込まれます。環境ファイル、オーケストレーターの環境変数定義、マウントされた設定ファイルを変更しても、実行中のデプロイには自動反映されません。

新しい設定で、対象の HTTP API レプリカ、ローカル Laravel キューワーカー、スケジューラープロセスをすべて再起動または置換してください。SDK Worker 自身のクライアント設定や Worker 設定を変更する場合は、常駐 SDK Worker も別途再起動します。API の再起動だけでは、実行中のキューワーカーやスケジューラーは更新されません。データベースとキャッシュを共有する各ロールで、意図した設定を揃えてください。

ローリング変更中は、各ノードが自身の読み込んだ制限を適用します。受付カウンターを共有していても、異なる設定のノードで制限が一致するわけではありません。同じリクエストが、ある API レプリカでは受け付けられ、別のレプリカでは拒否される場合があります。制限を一貫して切り替える必要がある場合は、次の手順を使用します。

  1. 呼び出し元からの新規送信を一時停止し、対象 API レプリカを入口のルーティングから外します。処理中のリクエストは完了させます。対象のキューとスケジューラーロールを、それぞれの終了猶予に従って正常終了させます。
  2. 対象のすべてのロールに同じ設定を適用し、再起動または置換します。各コンテナのエントリーポイントで設定キャッシュを再作成します。
  3. 起動ログの設定エラー、準備状態、変更した制限の動作を確認してから、入口と呼び出し元の送信を再開します。デプロイと準備状態のガイドを参照してください。

データベースに保存される運用設定は、別のライフサイクルに従います。以下の変更が成功すると、Server を再起動せずに、その後の操作で新しい値を使用できます。

設定即時変更範囲と制限
Namespace の説明と保持PUT /api/namespaces/{namespace}、または dw namespace:update保持ポリシーはその後の保持処理に適用されます。変更しても削除済みのデータは戻りません。Server の保持設定を参照してください。
Namespace の外部ペイロード保存ポリシーPUT /api/namespaces/{namespace}/external-storage保存済みの Namespace ポリシーを変更します。プロバイダーの認証情報、設定済みファイルシステムのディスクなどのプロセス設定には、上記の再起動が必要です。既存実行が参照するオブジェクトへのアクセスを維持してください。
Namespace の検索属性定義POST / DELETE /api/search-attributes後続リクエストが使用する登録情報を更新します。ワークフロー履歴を書き換えたり、環境変数によるサイズ・個数制限を置き換えたりはしません。

このリファレンスの DW_* の既定値と上限は、保存済み状態を変更する明示的なコントロールプレーン操作が文書化されている場合を除き、プロセス設定です。Server は設定ファイルの変更をポーリングしません。

契約の適用方法​

Server リポジトリの config/dw-contract.php が正式な契約です。コンテナ起動時の php artisan env:audit は、未知の DW_* 変数や従来の名前を検出すると警告します。警告を出して起動する代わりにエントリーポイントを失敗させるには、DW_ENV_AUDIT_STRICT=1 を設定します。

DW_ENV_AUDIT_STRICT=1
DW_AUTH_DRIVER=token
DW_ADMIN_TOKEN="${DW_ADMIN_TOKEN}"
DW_OPERATOR_TOKEN="${DW_OPERATOR_TOKEN}"
DW_WORKER_TOKEN="${DW_WORKER_TOKEN}"

従来の名前はフォールバック専用です。新しいデプロイでは常に DW_* 名を使ってください。Server が従来の値を引き続き使用できる場合でも、警告は解消すべき移行作業として扱います。

公開済みのフィンガープリント優先設定です。 Server 2.9.9 では、サービスモードの Worker にフィンガープリントの優先設定が適用されます。固定が有効な場合、記録済み定義を持つ適格な Worker が残っておらず、かつ置き換え Worker が workflow_entry_arguments_validation を通知している場合にだけ、変更後の定義へフォールバックできます。固定を無効にするとソースの優先は解除されますが、ビルド固定、名前空間・キュー・型の分離、登録識別情報、厳密なリプレイは維持されます。対応するエントリ保護は PHP SDK 2.5.4、Python SDK 2.6.2、Rust SDK 3.5.6 で導入されました。これらは機能の最小対応バージョンです。セキュリティ修正を含む最新の安定版をインストールしてください。古いランタイムの設定に同じキーがあるだけで、この動作を想定しないでください。定義ルーティングを参照してください。

CI とデプロイ用マニフェストには DW_V2_GUARDRAILS_BOOT を使用します。旧名 WORKFLOW_V2_GUARDRAILS_BOOT が残っているのは、env:audit が alpha 時代の運用者に名前の変更を案内するためだけです。Workflow パッケージは、この旧名を実行時のフォールバックとして読み取りません。

DW_V2_MATCHING_ROLE_QUEUE_WAKE または専用の workflow:v2:repair-pass --loop デーモンを設定する場合は、タスクのマッチングと配信を参照してください。これらの設定は実行可能タスクを検出する場所を変えるものであり、Worker プロトコルの契約自体を変えるものではありません。

実行基盤の変数​

実行基盤の変数は、フレームワークや依存ライブラリの設定です。Server の監査はこれらを認識して警告を抑えますが、安定した Durable Workflow API の設定項目ではありません。

分類変数用途
アプリケーションAPP_NAME、APP_ENV、APP_KEY、APP_DEBUG、APP_URL、APP_VERSION、ロケール、タイムゾーン、メンテナンス、暗号設定Laravel アプリケーションの実行時識別情報と起動動作。
ログLOG_CHANNEL、LOG_LEVEL、LOG_STDERR_FORMATTER、スタック、日次、Slack、Papertrail の設定Laravel のログ出力先、形式、保持。
データベースDB_CONNECTION、DB_HOST、DB_PORT、DB_DATABASE、DB_USERNAME、DB_PASSWORD、DB_SOCKET、DB_URL、DB_SSLMODE（DB_SSL_MODE）、DB_SSLROOTCERT（DB_SSL_ROOT_CERT）、MYSQL_ATTR_SSL_CA、文字セット、照合順序、外部キーの設定ワークフロー、Namespace、Worker、プロジェクションを保存する SQL データベース。データベース TLS を参照。
Redis・キャッシュ・キューREDIS_*、QUEUE_CONNECTION、QUEUE_FAILED_DRIVER、CACHE_STORE、CACHE_PREFIX、SESSION_*キューワーカー、キャッシュロック、ロングポーリング通知、Web・セッションの実行時サポート。
ファイルシステム・メール・配信FILESYSTEM_DISK、MAIL_*、BROADCAST_*、PUSHER_*、AWS_*デプロイ固有の機能で使用するフレームワーク連携。
ビルド・実行環境MYSQL_VERSION、REDIS_VERSION、PHP_CLI_SERVER_WORKERS、VITE_APP_NAME、BCRYPT_ROUNDSDocker Compose のイメージとフレームワークの実行時動作。

データベース TLS​

API サーバー、キューワーカー、初期化・マイグレーションジョブ、スケジューラーに 同じ TLS 設定を適用してください。PostgreSQL の既定値は prefer です。 MySQL/MariaDB はモード未指定時に従来の接続設定を使います。いずれの既定値も、 認証された暗号化接続を保証しません。

DB_SSLMODEPostgreSQLMySQL / MariaDB
disableTLS なし。TLS なし。矛盾する TLS オプションは拒否。
allow, prefer暗号化・接続先の識別を保証しない日和見的 TLS。拒否。
require暗号化必須。mysqlnd と OpenSSL による暗号化必須。
verify-ca暗号化と信頼できる証明書チェーンが必須。拒否。PDO mysqlnd はホスト名の検証と独立してチェーンだけを検証できない。
verify-full暗号化、信頼できるチェーン、ホスト名の一致が必須。暗号化、信頼できるチェーン、ホスト名の一致が必須。

DB_SSL_MODE は DB_SSLMODE、DB_SSL_ROOT_CERT は DB_SSLROOTCERT の 別名です。証明書を検証する場合、マイグレーションも含む すべてのロール に、 指定パスで読み取れる CA バンドルをマウントしてください。MySQL/MariaDB の明示的な verify-full では MYSQL_ATTR_SSL_CA も CA を指定できます。正規名・別名・URL の 設定が矛盾すると起動を拒否します。必須 TLS は明示的な TCP ホスト名を必要とし、 Unix ソケットは拒否されます。MySQL/MariaDB の明示的 TLS モードには mysqlnd と OpenSSL を備えた PDO MySQL が必要です。

DB_CONNECTION=pgsql
DB_HOST=database.example.com
DB_SSLMODE=verify-full
DB_SSLROOTCERT=/run/database-ca/ca.pem

証明書の DNS ホスト名を使ってください。Helm では externalDatabase.sslMode と externalDatabase.tls.existingSecret / caKey を設定します。インストール・ アップグレード前に Secret を作成してください。チャートが初期化フックを含む 全 4 ロールに CA をマウントします。起動時に設定がキャッシュされるため、 環境設定を変更したら常駐ロールを再起動してください。

コンテナのログ​

API、ワーカー、スケジューラーの各コンテナで LOG_CHANNEL=stderr を設定すると、 docker logs または kubectl logs でアプリケーションログを収集できます。 既存のリリースでは明示的に設定してください。LOG_LEVEL で最低重大度を選択します。 1 行に 1 レコードの JSON を出力するには、次も設定します。

LOG_STDERR_FORMATTER="Monolog\Formatter\JsonFormatter"

起動時に設定がキャッシュされるため、変更後は常駐プロセスを再起動してください。 ファイルチャネルを明示的に選ぶ場合は、保存先と収集方法を別途用意する必要があります。 Kubernetes は storage/logs/laravel.log を自動収集しません。 DW_LOG_FORMAT はサポートされる設定ではありません。

移行時の注意事項​

古いデプロイを移行する場合は、まず公開名へ変更し、旧名は未設定にします。両方が設定されている場合、運用時は DW_* の値を基準として考え、旧名を削除してください。

# Before
WORKFLOW_SERVER_AUTH_DRIVER=token
WORKFLOW_SERVER_OPERATOR_TOKEN=operator-secret

# After
DW_AUTH_DRIVER=token
DW_OPERATOR_TOKEN=operator-secret

移行後は DW_ENV_AUDIT_STRICT=1 で Server イメージを起動し、変数の誤記、古いエイリアス、旧手順書からコピーされた設定を検出してください。
