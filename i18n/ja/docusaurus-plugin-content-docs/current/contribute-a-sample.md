# サンプルを貢献する {#contribute-a-sample}

[サンプルアプリ](/docs/sample-app)は、Durable Workflow のパターンが実際の Laravel プロジェクトでどう見えるかを示す正式な場所です。まだ紹介していない Saga の形、メッセージストリームの別の使い方、既存サンプルが扱わないツールとの連携など、他のエンジニアに役立つパターンがある場合、このガイドに従ってマージまで進めてください。

この契約は意図的に短くしています。従ったサンプルは予測可能なペースで受け入れられます。一部を省略したサンプルは、不足が埋まるまでレビューに留まります。

## コードを書く前に {#before-you-write-code}

1. **最初に `sample-request` issue を作成します。** [`sample-request` テンプレート](https://github.com/durable-workflow/sample-app/issues/new/choose)には、対象パターン、それを定義する公開ドキュメント、必要な Durable Workflow パッケージの最低バージョンを記載します。貢献者が PR に労力を投じる*前*に、マージする価値があるとメンテナーと合意する場所が issue です。
2. **サンプル索引にまだないパターンを選びます。** [README サンプル索引](https://github.com/durable-workflow/sample-app#sample-index)には、対応済みの全パターンが載っています。「シンプルなワークフローの別の書き方」に帰着するアイデアは新しいサンプルではなく、`App\Workflows\Simple\SimpleWorkflow` のドキュメント修正です。
3. **最も近い既存ワークフロークラスを探します。** 新しいサンプルは隣のサンプルと同様に読めるべきです。`app/Workflows/<Pattern>/` 配下の同じディレクトリ構成、同じ artisan コマンド形式、同じテスト方針を使います。新しい足場を独自に作るサンプルは、紹介するパターンが良くても却下します。

## マージされるサンプルの形 {#what-a-merged-sample-looks-like}

マージされるサンプルは、*実行可能*で、*学習に役立ち*、*テストされ*、*見つけられる*ものです。これは sample-app リポジトリ内の四つの具体的な成果物に対応します。

1. **ワークフロークラス:** `app/Workflows/<Pattern>/` 配下に置き、パターンを最初から最後まで示します。ワークフローコードは決定的に保ちます。時刻の読み取りは `sideEffect()` 内、外部作業はアクティビティ内に置き、待機にはシグナル、更新、タイマー、メッセージストリームを使います。パターンが明示的に必要としない限り、ワークフロークラスは `OPENAI_API_KEY` などの外部認証情報なしでコンパイルできるようにします。
2. **artisan コマンド:** 現実的な入力でワークフローを開始し、読者が一つのコマンドで実行し、Waterline に実行が現れるのを見られるようにします。コマンドは `routes/console.php`（または同等の登録箇所）の対応する artisan コマンドの隣に置き、同じ命名規則（`app:<short-pattern>`）を使います。
3. **`config/workflow_mcp.php` エントリ:** ワークフロークラス、パターン、コマンド、必要な認証情報、引数を示します。これにより MCP サーバーからサンプルを検出できます。上流の網羅性 lint は、このエントリがあるまで対応行を `covered` にしません。
4. **`tests/` 配下のテスト:** インメモリの v2 Worker に対してワークフローを実行します。すべての型付き履歴イベントを検証する必要はありませんが、artisan コマンドが渡す入力でワークフローが完了することは証明しなければなりません。

機能ではなく*バグ修正*を示すサンプルは、同じ四つの成果物を持ち、代わりに `app/Workflows/Bug/<short-id>/` 配下に置きます。

## ドキュメントに含めるもの {#what-goes-in-the-docs}

サンプルの追加時には、三つのドキュメントを更新します。

- **sample-app リポジトリの README「Sample Index」:** サンプルごとに、目的、ワークフロークラス、artisan コマンド、MCP キーを一行で示します。これが正しい情報源です。
- **ドキュメントサイトのサンプルギャラリー（[`docs/sample-app.md`](/docs/sample-app)）:** 読者が見るはずの Waterline 画面を添えた対応行を複製します。リポジトリを clone する前に、欲しいサンプルか判断できるようにするためのギャラリーです。
- **パターンページからの相互リンク:** 対象機能を定義するサイトのパターンページ（Saga、シグナル、メッセージストリーム、子ワークフローなど）に追加します。sample-app ドキュメント末尾の相互リンク表が正式な一覧です。機能を示してもサンプルへリンクしないエントリは不足と扱います。

サンプルと README の変更は sample-app PR に、ギャラリーとパターンページの変更はリンクした docs-site PR に提出します。メンテナーは関連する変更をまとめて取り込みます。ドキュメントサイトの対応がないまま取り込まれたサンプルは、ドキュメント PR が追い付くまで上流の網羅性トラッカーで `gap` 状態になります。両方を一緒に提出することを推奨します。

## 命名、配置、スタイル {#naming-layout-and-style}

- **クラス配置:** `app/Workflows/<Pattern>/<Pattern>Workflow.php`。アクティビティクラスは隣の `app/Workflows/<Pattern>/Activities/` に置きます。バグ再現は同じ構成で `app/Workflows/Bug/<short-id>/` に置きます。
- **artisan コマンド:** `app:<short-pattern>`（小文字、ハイフンなし）。長い形式（`app:run-<pattern>`）は使いません。
- **MCP キー:** artisan コマンドの短いパターン名と一致させ、ターミナルで人が入力するのと同じ名前を MCP クライアントが見るようにします。
- **コメント:** *何をするか*より*理由*を書きます。リプレイ安全性の不変条件（値を `sideEffect()` で包む理由、`usleep()` でなくタイマーで待つ理由）はコメントに値します。全アクティビティ呼び出しに同じコメントを付ける必要はありません。
- **Waterline スクリーンショット:** ドキュメントサイトのギャラリーは、サンプルが生成するはずの Waterline 画面を示します。サンプル PR の一部として、その画面を追加または更新してください。

## サンプルが差し戻される条件 {#what-gets-a-sample-rejected}

次の場合、サンプルを差し戻します。

- ワークフローコードが `sideEffect()` やアクティビティの外で `now()`、`random_*()` などの非決定的呼び出しを使う
- エンジンが既に所有する永続的な管理作業をアクティビティが行う。`workflow_messages` 行への直接書き込み、ストリームカーソルの手動進行、ワークフローコードからの Waterline 状態の永続化など
- artisan コマンドが外部認証情報を必要とするのに、MCP エントリの `requires` に記載しない
- README のサンプル索引、サイトのギャラリー行、パターンページの相互リンクを同じ変更で取り込まない
- 異なる形、失敗モード、連携などの新しい点を示さず、既存パターンを再現する。「同じパターンで文章だけ違う」はサンプルではなくドキュメント変更です

これらは、上流の網羅性 lint と sample-app レビューチェックリストが確認する内容と同じです。PR を作る前に自分で見つけるのが、マージへの最短経路です。

## 簡易チェックリスト {#quick-checklist}

PR 作成時に使ってください。

- [ ] `sample-request` issue があり、公開パターンドキュメントへリンクしている。
- [ ] `app/Workflows/<Pattern>/` 配下のワークフロークラス。
- [ ] `app:<short-pattern>` 名で登録した artisan コマンド。
- [ ] class、pattern、command、requires、arguments を持つ `config/workflow_mcp.php` エントリ。
- [ ] 最初から最後までワークフローを実行するテスト。
- [ ] README「Sample Index」の行。
- [ ] [`docs/sample-app.md`](/docs/sample-app) のサイトギャラリー行。
- [ ] サイトの対応するパターンページからの相互リンク。
- [ ] 公開境界スキャン（`scripts/check-public-boundary.sh`）が問題なし。

メンテナーもレビューで同じ一覧を使います。すべてを満たす PR は、通常一つのリリースサイクル内で取り込まれます。
