# 制約の概要 {#constraints-summary}

| 制約 | ワークフローのコード | アクティビティのコード |
| --- | --- | --- |
| IO | 不可 | 可 |
| 変更可能なグローバル変数 | 不可 | 可 |
| 非決定的な関数 | 不可 | 可 |
| `Carbon::now()` | 不可 | 可 |
| `sleep()` | 不可 | 可 |
| 外部への副作用 | アクティビティに移す | 繰り返しても安全な場合のみ可 |

ワークフローのコードには決定性が必要です。エンジンは永続化されたステップの履歴をリプレイして状態を再構築し、アクティビティではなくワークフロー本体を再実行します。本体がリプレイ時に異なる判断をすると、状態を再構築して正しく実行を続けられません。本体に冪等性は不要です。リプレイが要求するのは決定性です。

アクティビティは少なくとも1回実行されるため、冪等でなければなりません。リトライ、リースの失効、再配信により同じ試行が複数回観測されることがあります。これはエラーではなく、正式に想定された動作です。冪等性キー、決定的な対象リソース、元々冪等な操作を使って、本体や外部の対象を繰り返しても安全にすることで、重複実行による副作用の重複を防ぎます。

2つの性質の比較と、それぞれを区別する例は[冪等性と決定性](/docs/constraints/idempotent-vs-deterministic/)を参照してください。

これらの用語が表す公開 v2 契約は[実行保証と冪等性](./execution-guarantees.md)を参照してください。
