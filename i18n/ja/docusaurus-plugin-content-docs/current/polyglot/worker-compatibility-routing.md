# ワーカーの互換性とルーティング

互換性はルーティングの契約です。新規開始用ビルドを変更しても、既存履歴をリプレイできるワーカーを残してください。ドレインで実行が他ビルドへ移ることはありません。

## 関連する二つの識別子 {#two-related-identities}

- **ビルドID**は、スタンドアロンServerのコホートが登録する`build_id`です。範囲は名前空間とキューで、昇格、ドレイン、再開はこのコホートに作用します。
- **互換性マーカー**は永続的な仕事に記録されます。組み込みPHPでは`DW_V2_CURRENT_COMPATIBILITY`と`DW_V2_SUPPORTED_COMPATIBILITIES`を使い、スタンドアロンワーカーのビルドIDは対応するルーティング識別子になります。

値は不透明な文字列として扱います。新しく見える名前はリプレイ互換性を証明せず、既存ピンを変更する権限にもなりません。

## 固定されるもの {#what-gets-pinned}

スタンドアロンServerは新規開始のピンを明示的な昇格から選び、次に単一アクティブコホートへのフォールバックを使います。曖昧なら未固定になる場合があります。[選択順序](/docs/polyglot/worker-build-id-rollout#canary-a-new-build)を参照してください。

ワークフロータスクとアクティビティは実行の互換性を継承します。タスク再試行、リース切れ、再配送でも維持されます。再試行実行、子、continue-as-newも元のピンを継承します。昇格は以降の新インスタンスに作用し、継続中のチェーンを新ビルドへ移しません。

## ルーティングの仕組み {#how-routing-works}

### poll時の絞り込み {#poll-time-narrowing}

ワーカーは名前空間、キュー、互換ビルドコホートを要求します。poll選択は互換性のない仕事の提示を避けますが、最終的な権限境界ではありません。

### 取得時の検証 {#claim-time-enforcement}

取得時にはタスクの元の互換性とワーカー識別を確認します。他のビルドが不在でも、非互換ワーカーはそのリースを得られません。リース切れで互換性の範囲が広がることもありません。

## 運用者が設定する項目 {#what-operators-should-configure}

組み込みPHPでは、現在の系列と明示的に対応する系列を設定します。

```bash
DW_V2_CURRENT_COMPATIBILITY=orders-2026-04-28
DW_V2_SUPPORTED_COMPATIBILITIES=orders-2026-04-28,orders-2026-04-21
```

最初の値は新しい組み込み実行を固定し、二つ目はそれらの系列の取得を許可します。`*`は意図して検証した互換性方針がある場合にのみ使ってください。スタンドアロンワーカーは安定した`build_id`を登録し、Serverの昇格とライフサイクル制御を使います。リプレイ互換の再ビルドでは系列を保ちます。ラベルを変えても非互換コードは安全にリプレイできません。

## 安全なロールアウト手順 {#safe-rollout-pattern}

1. 新コホートを配備し、名前空間、キュー、対応型、最新登録を確認します。旧コホートも維持します。
2. 以降の新規開始用ビルドを明示的に昇格します。ワーカー数は割合によるトラフィック配分ではありません。
3. 固定された実行の互換容量を保ちます。タイマー、シグナル、アクティビティ、子を待つ受動的な実行も含みます。
4. そのコホートの新規取得を意図的に止めるときだけドレインします。早すぎるドレインで停止したら、再開して元の互換ビルドを復旧します。
5. 新規開始を戻すには、既知の正常コホートを復旧／再開して昇格し、その後不良デプロイをロールバックします。既存ピンは変わりません。

未完了タスク0件は安全な廃止の証拠ではありません。固定実行や継承されたチェーンが必要とする間は成果物と復旧経路を残します。別途の保護された廃止機能は[Server #519](https://github.com/durable-workflow/server/issues/519)で追跡しており、この手順が提供するものではありません。

## 互換ワーカー不在の明示状態 {#explicit-missing-worker-state}

[コホート別の未完了タスク](/docs/polyglot/worker-build-id-rollout#pending-workflow-tasks-by-cohort)、最新／ドレイン中／古い登録、元のピンを合わせて確認します。`no_compatible_worker`は、非nullビルドの未完了ワークフロー仕事にアクティブ互換ワーカーがいないことを示します。アクティビティキューや全ての受動的な固定実行を数えるものではありません。欠落フィールド、要求失敗、古いheartbeatを、空のフリートや0件として扱わないでください。無関係なワーカーを増やす前に対象ビルドを復旧するか、キュー、名前空間、型宣言を調べます。

## ビルドIDロールアウトとの関係 {#how-this-relates-to-build-id-rollouts}

ロールアウト状態は登録容量と新規開始／ライフサイクルの意図を示し、互換性は特定の元タスクを取得できるかを決めます。両方を使ってください。ドレインもロールバックも永続互換性を書き換えず、ビルドを削除できる証明にはなりません。
