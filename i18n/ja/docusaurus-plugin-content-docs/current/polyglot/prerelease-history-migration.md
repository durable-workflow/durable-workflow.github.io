# 保持されたプレリリース履歴の移行 {#migrate-retained-prerelease-history}

Avro 専用の Durable Workflow 2.0 デプロイが、以前の公開 2.0 プレリリースから保持した状態について `unsupported_payload_codec` を報告する場合、このオフライン手順を使います。稼働中の v2 アプリケーションに旧コーデックを公開することなく、既知の JSON タグ付き、タグなし、古い Avro Value 表現を変換します。

この手順の代わりに履歴エクスポートを使わないでください。エクスポートは実行の移植可能なコピーであり、デプロイの起動時に検査するデータベース行を変更しません。事前チェックを通すために履歴を削除してはいけません。

## 変換が必要な対象を判断する {#decide-what-must-be-converted}

まだ有効な実行は現在デプロイされているプレリリースで完了できます。運用上安全であれば、保守時間帯までに完了させてください。終了済みの実行、リプレイ用に保持する閉じた実行、完了を待てない状態は変換が必要です。移行は両方のグループを調査し、どちらも削除しません。

ドライランは Server 起動時に検査する、プロトコルが管理する次のサーフェスを対象にします。

- ワークフローの入力と出力、アクティビティペイロード、コマンド、シグナル、更新、サービス呼び出し、更新検証タスク、永続ストリーム参照。
- インラインの single-object フレームと、履歴イベントにネストした明示的なペイロードエンベロープ。
- 参照の構造、コーデック、オブジェクトの存在、バイト長、SHA-256 の整合性を含む外部保存ペイロード参照。

利用者が管理する memo、検索属性、コンテキスト、診断のマップはコーデック宣言ではないため変更しません。未知のコーデック、未知のスキーマフィンガープリント、破損した参照、固定の Avro Value スキーマで表せない値は安全でないと報告します。安全でない項目があると適用をブロックします。

## 所有権の境界 {#ownership-boundary}

コマンドは Workflow PHP パッケージに属しますが、データベース接続と外部ペイロード設定を所有するプロセスで実行する必要があります。

- **組み込み Laravel:** アプリケーションのチェックアウトに対象の Workflow パッケージをインストールし、Web、キュー、スケジューラー、保守の各プロセスを停止した状態で、アプリケーションの `php artisan` コマンドを実行します。
- **スタンドアロン Server:** 対象の Server イメージから一回限りのシェルまたはジョブを使い、デプロイと同じデータベース、名前空間設定、認証情報、外部ペイロードのマウントを与えます。変換が成功するまで通常のブートストラップフックとすべての Server プロセスを停止したままにします。

無関係なアプリケーションのチェックアウトをこのデータベースへ向けないでください。名前空間のストレージポリシーは整合性検査の一部です。外部オブジェクトを読めないプロセスは推測せず、安全でないと報告します。

## デプロイの順序 {#deployment-order}

1. 完了を待つことを選んだ有効な実行が終わるまで、古いプレリリースを利用可能な状態に保ちます。その後、API ノード、Worker、スケジューラー、ブートストラップジョブ、保守ジョブを含む、データベースへ書き込むすべてのプロセスを停止します。
2. 通常の復旧ポリシーで必要なデータベースと外部オブジェクトストアのスナップショットを取得します。古いアプリケーションまたは Server の成果物を保持します。
3. `workflow:v2:migrate-prerelease-history` を含む対象成果物をインストールまたは取得しますが、起動はしません。その成果物からドライランの調査を実行します。

   ```bash
   php artisan workflow:v2:migrate-prerelease-history --dry-run --json
   ```

   終了コード 0 は、影響するすべての値を安全に変換できることを意味します。パスと影響する実行 ID を確認してください。非ゼロの終了コードで `unsafe_fields` が 0 より大きい場合、アップグレードはブロックされます。ストレージアクセスを修正するか、古いプレリリースに留まってください。
4. 永続ストレージ上で、新しい非公開バックアップパスと新しい非公開証跡ディレクトリを選びます。どちらも既存であってはいけません。一度適用します。

   ```bash
   php artisan workflow:v2:migrate-prerelease-history \
     --backup=/secure/dw-prerelease-history-backup.json \
     --evidence-dir=/secure/dw-prerelease-history-evidence
   ```

   コマンドは更新を始める前にバックアップを書き込み、証跡の上書きを拒否します。単一トランザクションでデータベース行をロックして更新し、ワークフローと実行の ID を保持し、外部オブジェクトのハッシュとサイズを検証し、元のすべての外部オブジェクトを保持します。代替の外部オブジェクトは内容アドレス方式の Avro コピーです。履歴は削除しません。
5. コマンドの完了を待ちます。影響する保持済み実行をすべてエクスポートして厳密にリプレイし、概要、待機、タイムライン、タイマー、系譜のプロジェクションを再構築し、ずれを検査し、ペイロード調査を繰り返します。成功には3つすべての検査が必要です。生成されたリプレイとプロジェクションの報告をバックアップとともに保持します。
6. 移行が成功してから通常の対象ブートストラップを実行します。

   ```bash
   php artisan server:bootstrap --force
   ```

   組み込み Laravel では、代わりにアプリケーションの通常の移行・ブートストラップ手順を実行します。新しい Worker、API ノード、スケジューラー、保守プロセスを起動する前に、Avro 専用ペイロードの事前チェックが問題なく完了する必要があります。
7. 対象のデプロイを開始し、準備状態と、通常の運用サーフェスを通じた保持済み実行のリプレイまたはクエリを検証します。ロールバック期間中は移行一式を保持します。

## ロールバック {#rollback}

適用、リプレイ、プロジェクション検証、事後チェックのいずれかが失敗すると、アップグレードはブロックされます。すべての書き込みプロセスを停止したまま、移行が表示したロールバックコマンドを実行してください。上記のパスでは次のとおりです。

```bash
php artisan workflow:v2:migrate-prerelease-history \
  --rollback-from=/secure/dw-prerelease-history-backup.json \
  --evidence-dir=/secure/dw-prerelease-history-evidence
```

ロールバックはバックアップのダイジェストと移行状態を検証し、ロールバック証跡の上書きを拒否し、変換後に変更された行の復元を拒否します。元のデータベース値をアトミックに復元し、代替の外部オブジェクトは証跡として保持します。その後、以前のアプリケーションまたは Server 成果物を復元します。別の書き込み元が状態を変更したためにロールバックが拒否された場合、アップグレードはブロックしたまま、手順2で連携して取得したデータベースとオブジェクトストアのスナップショットを復元してください。

ロールバック後、Avro 専用デプロイの事前チェックは再び失敗する想定です。報告された安全でない状態を解決し、新しいバックアップと証跡のパスを作り、アップグレードを再試行する前に手順全体を繰り返してください。
