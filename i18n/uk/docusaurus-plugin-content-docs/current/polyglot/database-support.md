# Сумісність і кваліфікація баз даних

Використовуйте цю таблицю для вибору бази вбудованого Laravel і самостійно розгорнутого Server. Cloud керує власним сховищем runtime. Клієнти Cloud налаштовують клієнти SDK та worker, а не базу runtime.

Заявлена база сумісності не доводить кваліфікацію кожної новішої версії. Тести коду й установлені опубліковані артефакти є різними доказами. Цей зріз прив’язаний до коду Workflow 2.20.3 і квитанцій Server 3.0.5. Він не змінює сумісність і не встановлює перевіреного мінімального/максимального діапазону.

| Рушій | Заявлена сумісність | Спостережена кваліфікація коду | Кваліфікація опублікованого артефакту |

## Як читати докази {#reading-the-evidence}

[Інвентар Core](https://github.com/durable-workflow/durable-workflow.github.io/issues/347#issuecomment-6642279325) прив’язує початкові digests образів і чотири MySQL, чотири PostgreSQL та один MariaDB feature job до випущеного коду. Його дванадцять клітинок оновлення пакета охоплюють Laravel/PHP, а не дванадцять endpoint баз даних. Окрема [квитанція звичайно встановленого Core](https://github.com/durable-workflow/workflow/pull/1025#issuecomment-6632522927) охоплює 67 stream/replay/fake випадків із SQLite. Ані версія PHP, ані плаваючий селектор образу не надає невиведеної версії бази.

[Інвентар Server](https://github.com/durable-workflow/server/issues/563#issuecomment-6642659277) розділяє обсяг jobs нативного коду й попереднього PHP. [Квитанція стабільного 3.0.5](https://github.com/durable-workflow/server/issues/563#issuecomment-6643169603) має чотири Compose smoke клітинки архітектури/профілю. `local` і `production` використовують MySQL. Перевірені журнали не відновлюють точну версію/digest супутньої бази, перевірку записувальної ємності чи підтверджений TLS. Профілі коду й заморожений кандидат не кваліфікують іншого опублікованого образу.

## Життєвий цикл постачальника та розподілені рушії {#vendor-lifecycle-and-distributed-engines}

Для нових розгортань обирайте підтримувані постачальником лінії після кваліфікації точної пари runtime/база. [Політика PostgreSQL](https://www.postgresql.org/support/versioning/) позначає 13 непідтримуваним, підтримка 14 закінчується 12 листопада 2026. За [повідомленням Oracle](https://www.mysql.com/support/eol-notice.html), MySQL 8.0 перебуває в Sustaining Support із 21 квітня 2026. Життєвий цикл постачальника не встановлює й не скасовує нашу кваліфікацію артефактів.

TiDB, Vitess, PlanetScale та інші розподілені MySQL-сумісні розгортання тут не перевірені. Протокольна сумісність не доводить ізоляцію транзакцій, блокування рядків, видимість commit/after-commit чи поведінку повторів. Перевірте цю семантику з точним runtime перед упровадженням. Таблиця не розширює [однорегіонний операційний контракт](../operator-operating-envelope.md) на кілька регіонів.
