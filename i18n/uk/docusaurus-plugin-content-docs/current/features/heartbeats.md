# Heartbeat {#heartbeats}

Heartbeat дають тривалій activity змогу повідомляти, що її поточна спроба досі працює.

`heartbeat()` оновлює поточний захоплений рядок `activity_attempts` часом heartbeat і останнім прогресом, віддзеркалює останній heartbeat в активному виконанні activity та подовжує lease цього завдання activity. Подію історії `ActivityHeartbeatRecorded` він записує лише тоді, коли прогрес змінився, і не частіше одного разу за інтервал запису (див. нижче). Детальний перегляд вибраного запуску у Waterline та експорт історії беруть останній heartbeat і прогрес із рядка спроби, а статус спроби, ідентифікатор завдання, worker, lease, скасування й час закриття відновлюють із типізованої історії `ActivityStarted`, `ActivityHeartbeatRecorded`, `ActivityRetryScheduled`, `ActivityCompleted`, `ActivityFailed` і `ActivityCancelled`, а для старіших даних використовують рядки спроб як запасний варіант.

```php
use Workflow\V2\Activity;

final class PollRemoteJob extends Activity
{
    public function handle(string $jobId): array
    {
        do {
            sleep(1);

            $status = RemoteService::status($jobId);

            $this->heartbeat([
                'message' => 'Polling remote job',
                'current' => $status['completed'] ?? null,
                'total' => $status['total'] ?? null,
                'unit' => 'steps',
                'details' => [
                    'remote_state' => $status['state'] ?? 'running',
                ],
            ]);
        } while ($status['state'] === 'running');

        return $status;
    }
}
```

Усередині activity методи `activityId()`, `attemptId()` та `attemptCount()` надають ідентичність стійкого виконання й поточної спроби, якщо потрібні ключі кореляції для зовнішньої роботи. Типовим ключем ідемпотентності віддаленої роботи обирайте `activityId()`. Використовуйте `attemptId()` лише для систем, яким потрібно розрізняти окремі спроби одного стійкого виконання activity.

Worker різних мов можуть надсилати heartbeat через HTTP-міст worker без створення екземпляра PHP-класу activity. Кінцеві точки наведено в [протоколі worker](/docs/polyglot/worker-protocol).

Окремий блокувальний виклик може потребувати допоміжного потоку для heartbeat.
Це підтверджує життєздатність, а не прогрес. Задайте виклику власний скінченний
термін і зупиніть допоміжний потік після завершення або втрати повноважень.
У Python дотримуйтеся [прикладу зі збереженням контексту та скасуванням](../polyglot/python.md#heartbeat-helper-thread).

## Періодичність і підтвердження {#heartbeat-cadence-and-receipts}

Для activity у черзі перший кінцевий термін heartbeat починається, коли runtime отримує її завдання, ще до доставлення завдання та користувацького коду. Записаний heartbeat встановлює наступний термін як свій час у runtime плюс `heartbeatTimeout`. Надсилання запиту чи отримання відповіді не починає нового повного вікна. Див. [Тайм-аут heartbeat](./timeouts.md#heartbeat-timeout).

Виберіть періодичність із великим запасом усередині цього вікна й обмежуйте роботу між викликами. За тайм-ауту 15 секунд орієнтир близько п’яти секунд може бути початковою точкою лише якщо доставлення, кожен пакет чи виклик вводу-виводу, паузи виконання, мережева затримка й транспортні повтори вкладаються в решту бюджету. Вимірюйте ці затримки та залишайте запас. Це порада для планування, а не гарантовано безпечний інтервал. Прострочена чи замінена спроба не відновлює оренду пізнім heartbeat.

Автоматичного розкладу heartbeat із прогресом або гарантії пакетування в SDK немає. Heartbeat реєстрації worker і перевірки стану володіння не публікують прогрес activity. Кожен прийнятий heartbeat подовжує lease і зсуває дедлайн heartbeat. Подія історії записується лише тоді, коли прогрес відрізняється від останнього записаного і з моменту тієї події минуло щонайменше більше з двох значень: тайм-аут heartbeat або 60 секунд. Heartbeat без прогресу лише підтверджує активність і нічого не записує в історію. Прогрес, відкладений через інтервал, записується один раз під час закриття спроби. Heartbeat щосекунди протягом години без зміни прогресу записує одну подію. Старіші історії зберігають уже записані події для кожного heartbeat.

У вбудованому режимі `Activity::heartbeat()` повертає `void`. Некоректний прогрес і збої сховища можуть спричиняти винятки. Звичайне повернення не є об’єктом підтвердження: закрита, прострочена чи замінена спроба може повернутися, не записавши нового heartbeat. У сервісному режимі обробка помилок відрізняється для прямих викликів клієнта та керованих workers. Див. настанови для [PHP](../polyglot/php.md#activity-heartbeats), [Python](../polyglot/python.md#activity-heartbeat-requests) і [Rust](../polyglot/rust.md#activity-heartbeats).

Прогрес heartbeat не фіксує зовнішній пакет атомарно й не відгороджує зовнішні ефекти від застарілого виконавця. Безпечна для повторних спроб контрольна точка програми потребує власного сталого commit, стабільного логічного ключа роботи та ідемпотентності або зовнішньої перевірки повноважень. Доступ замінної спроби до підтверджених контрольних точок відстежується окремо у [функції контрольних точок](https://github.com/durable-workflow/.github/issues/218).

## Знімки прогресу {#progress-snapshots}

`Activity::heartbeat()` та `ActivityTaskBridge::heartbeat()` приймають необов’язковий знімок прогресу з обмеженим розміром:

- `message`
  - непорожній рядок завдовжки до 280 символів
- `current`
  - невід’ємне ціле число або число з рухомою комою
- `total`
  - невід’ємне ціле число або число з рухомою комою
- `unit`
  - непорожній рядок завдовжки до 64 символів
- `details`
  - пласка мапа з не більш ніж 20 записів `key => scalar|null`, де ключі відповідають `[A-Za-z0-9_.:-]{1,64}`

Використовуйте ці дані для показу прогресу оператору, наприклад `"Downloading chunk"` або `2 / 5 chunks`, а не для великих журналів чи довільного вкладеного стану. Детальний перегляд вибраного запуску у Waterline, запис heartbeat у хронології та експорт історії повертають їх у полі `last_heartbeat_progress` activity й поточної спроби. Необроблена типізована подія історії `ActivityHeartbeatRecorded` зберігає ті самі нормалізовані дані в `progress`.

## Стійке відстеження спроб {#durable-attempt-tracking}

Середовище виконання зберігає один повноцінний довговічний рядок для кожної спроби activity: номер спроби, статус, час початку, останній heartbeat і прогрес, закінчення lease та час закриття. Воно також записує типізовану історію спроби, коли activity стартує, надсилає heartbeat, повторюється, завершується, падає або скасовується, тож історичні дані спроби зберігаються, навіть якщо змінні рядки спроби чи завдання пізніше розійдуться. Записаний heartbeat додає компактну точку хронології `ActivityHeartbeatRecorded` з ідентифікатором виконання activity, ідентифікатором спроби, часом heartbeat, закінченням lease, прогресом і знімком activity на момент події. Якщо команда cancel або terminate закриває запуск, міст записує `ActivityCancelled`, коли worker помічає зупинку, і відхиляє пізніше завершення чи помилку як застарілі, а не перетворює скасування на результат.

Heartbeat — це операційні сигнали активності. Надсилайте heartbeat так часто, як цього потребують ваші тайм-аути та відновлення. Heartbeat лише для підтвердження активності не додають історії, а зміни прогресу записуються не частіше одного разу за інтервал. Тримайте необов'язковий знімок прогресу достатньо компактним для операторської діагностики, а не використовуйте його як потік подій.
