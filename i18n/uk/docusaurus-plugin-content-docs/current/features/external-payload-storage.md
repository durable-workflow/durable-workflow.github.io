# Зовнішнє сховище даних {#external-payload-storage}

У вбудованому Laravel зовнішнє сховище замінює великі закодовані значення в історії workflow перевіреними посиланнями на сховище застосунку. Ця сторінка описує саме цю межу. Клієнти й worker у сервісному режимі використовують [транспорт runtime Server](../polyglot/server-api-reference.md#runtime-external-payload-transport): Server зберігає облікові дані провайдера, а SDK обмінюються непрозорими ідентифікаторами посилань через автентифікований HTTP. URI провайдера не є припустимим конвертом даних Server.

## Коли використовувати {#when-to-use-it}

Використовуйте зовнішнє сховище для великих документів, медіа, звітів, аргументів або результатів activity, які справді потрібно передавати через durable execution. Малі значення залишаються вбудованими й не потребують запису до об’єктного сховища. Винесення даних не скасовує обмежень розміру, кількості подій історії чи кількості об’єктів, які утримує run.

## Як працює винесення даних {#how-offload-works}

Політика namespace застосунку надає драйвер сховища й додатний `threshold_bytes`. Закодовані дані, розмір яких **перевищує** поріг, записуються через драйвер. Значення, рівні порогу або менші за нього, залишаються вбудованими. Вимкнена політика або відсутній драйвер також залишає значення вбудованими.

Вбудоване посилання провайдера має схему `durable-workflow.v2.external-payload-reference.v1` з полями `uri`, `sha256`, `size_bytes`, `codec` і необов’язковим `expires_at`. Кодек — `avro`. `Workflow\V2\Support\ExternalPayloads` зберігає закодований конверт із префіксом `dw-external-payload:v1:`. Коли runtime потрібне значення, він отримує закодовані байти та перевіряє розмір і SHA-256 перед декодуванням. Відсутні або змінені байти спричиняють помилку, а не підстановку `null`.

Це посилання провайдера відрізняється від схеми Server `durable-workflow.v2.runtime-external-payload-reference.v1`. Перш ніж переносити допоміжну функцію драйвера чи збережений конверт між режимами, перегляньте [таблицю підтримки](../polyglot/server-api-reference.md#external-payload-support-by-mode).

## Межа довіри під час декодування {#decode-trust-boundary}

Зберігання й декодування мають окремі межі довіри. Провайдер може зберігати закодовані байти, тоді як worker, сервер кодеків або інструмент експорту, що їх декодує, бачить значення застосунку. Визначте місце роботи декодерів, доступні їм ключі та правила приховування даних у перегляді й журналах. Хеші, розміри й назви кодеків є метаданими цілісності, а не гарантією наскрізного шифрування. URI провайдера теж можуть містити конфіденційні назви об’єктів.

## Вибір драйвера {#driver-choices}

| Драйвер | Схема URI | Вимога у вбудованому режимі |
| --- | --- | --- |
| Локальна файлова система | `file://` | Кожен вбудований процес, що розв’язує посилання, має бачити той самий кореневий каталог сховища. |
| S3-сумісне сховище | `s3://` | Драйвер або файловий диск застосунку з відповідними bucket, префіксом і обліковими даними. |
| Google Cloud Storage | `gs://` | Драйвер або файловий диск застосунку й клієнт провайдера. |
| Azure Blob Storage | `azure://` | Драйвер або файловий диск застосунку й клієнт провайдера. |

Server може використовувати локальне сховище, а віддалені SDK worker отримуватимуть дані через HTTP. Таким worker не потрібні спільна файлова система чи облікові дані провайдера.

## Налаштування namespace {#configuring-a-namespace}

Вбудовані застосунки налаштовують політику сховища namespace і `ExternalPayloadStorageDriver` у своєму Laravel runtime. Зберігайте облікові дані в конфігурації застосунку, а не в аргументах workflow, історії чи URI посилань. Використовуйте узгоджену політику в усіх процесах, що виконують і відтворюють run.

У self-hosted Server адміністративний [API сховища namespace](../polyglot/server-api-reference.md#namespace-and-storage) і [команди CLI для сховища](../polyglot/cli-reference.md#namespace-and-search-attribute-commands) налаштовують політику Server. Вони не надають SDK worker прямий доступ до провайдера.

### Через CLI {#with-the-cli}

`dw namespace:set-storage-driver` налаштовує namespace Server, а не Laravel-контейнер окремого вбудованого застосунку. Обов’язкові параметри диска, bucket і префікса наведені в довіднику CLI.

### Через API Server {#with-the-server-api}

`PUT /api/namespaces/{namespace}/external-storage` — адміністративна операція політики. Звичайні SDK клієнти виявляють налаштований транспорт runtime через `GET /api/cluster/info`, а не копіюють конфігурацію провайдера до worker.

## Перевірка політики {#verifying-the-policy}

Передайте значення, більше за поріг, через фактично налаштований драйвер і процеси, які виконуватимуть replay. Після отримання перевірте точну довжину закодованих байтів і SHA-256. Для політики Server команда `dw storage:test --namespace=billing --json` перевіряє налаштований шлях сховища. Діагностика сховища не доводить виконання workflow в кожному SDK, відновлення резервних копій чи роботу всіх адаптерів провайдерів.

## Вибір порога {#picking-a-threshold}

Обирайте поріг із запасом до звичайних обмежень запиту й даних. Він стосується **закодованих байтів**, а не розміру початкового файлу чи бізнес-JSON. Надто малий поріг додає запити до сховища й утримувані посилання для малих значень. Транспорт runtime може також виносити додаткові значення, щоб сукупний HTTP-запит умістився в ліміт. У сервісному режимі використовуйте виявлені ліміти Server, а не вважайте поріг вбудованого режиму лімітом протоколу.

## Replay, зберігання й очищення {#replay-retention-and-cleanup}

- **Цілісність replay.** Значення декодується лише після отримання й перевірки байтів за посиланням. Зберігайте об’єкти для кожного утримуваного run, якому вони ще потрібні.
- **Кеш перевірених отримань.** `ExternalPayloadStorage` обмежує кеш перевірених байтів. Очищення кешу не видаляє об’єкт і не змінює його власника.
- **Політика зберігання.** Очищення runtime враховує утримуваних власників і спільні об’єкти. Збої сховища, блокування для резервних копій чи решта посилань можуть затримати видалення. Запущена retention-процедура не гарантує відсутності осиротілих об’єктів.
- **Експорт історії.** Експорт може зберегти метадані посилання, не отримуючи сам об’єкт. Контрольна сума чи прапорець `history_complete` не доводять наявності зовнішніх байтів або можливості replay архіву. Дотримуйтеся [межі резервного копіювання й відновлення](../configuration/pruning-workflows.md#export-before-pruning) та перевіряйте об’єкти окремо. Самодостатні архіви відстежуються в [Server #520](https://github.com/durable-workflow/server/issues/520).

## Використання з коду {#using-it-from-code}

Вбудований PHP використовує `Workflow\V2\Support\ExternalPayloadStorage` з `ExternalPayloadStorageDriver`. `LocalFilesystemExternalPayloadStorage` працює з локальними кореневими каталогами. Адаптери провайдерів визначають власні налаштування доступу й правила URI. Застосунки зазвичай дозволяють runtime застосовувати політику namespace, а не конструюють збережені конверти вручну.

У сервісному режимі клієнти й worker PHP, Python та Rust SDK автоматично завантажують і отримують дані runtime, якщо Server оголошує доступний транспорт. Не надсилайте Server конверт провайдера `external_storage` і не видаляйте об’єкти Server через допоміжні функції прямого доступу до провайдера. Дивіться [контракт завантаження й отримання](../polyglot/server-api-reference.md#runtime-external-payload-transport) і [межу допоміжних функцій Python](../polyglot/python.md#external-payload-storage).
