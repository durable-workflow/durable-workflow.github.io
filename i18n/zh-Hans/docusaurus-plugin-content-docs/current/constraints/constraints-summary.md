# 约束汇总 {#constraints-summary}

| 约束 | 工作流代码 | 活动代码 |
| --- | --- | --- |
| IO | 不允许 | 允许 |
| 可变全局变量 | 不允许 | 允许 |
| 非确定性函数 | 不允许 | 允许 |
| `Carbon::now()` | 不允许 | 允许 |
| `sleep()` | 不允许 | 允许 |
| 外部副作用 | 移至活动中 | 仅在可安全重复时允许 |

工作流代码必须具有确定性，因为引擎通过重放持久步骤的历史来重建工作流状态。它会重新调用工作流主体，而非活动。如果主体在重放时作出不同的决策，引擎就无法正确重建状态并继续执行。工作流主体不需要具有幂等性；重放要求的是确定性。

活动必须具有幂等性，因为活动执行遵循至少一次语义。重试、租约过期和重新投递可能使同一次尝试被观察多次，这是预期行为。使用幂等键、确定的目标资源或天然幂等的操作，让活动主体或其外部目标可以安全重复执行，才能避免重复执行产生重复副作用。

参阅[幂等性与确定性](/docs/constraints/idempotent-vs-deterministic/)，通过直接比较和示例理解这两种独立属性。

这些术语背后的 v2 公开契约见[执行保证与幂等性](./execution-guarantees.md)。
