# 迁移保留的预发布历史 {#migrate-retained-prerelease-history}

当仅支持 Avro 的 Durable Workflow 2.0 部署针对早期公开 2.0 预发布版保留的状态报告 `unsupported_payload_codec` 时，使用此离线流程。它转换已知的带 JSON 标签、未标记和过时的 Avro Value 表示形式，不会向正在运行的 v2 应用开放任何旧编解码器。

不要以历史导出代替此流程。导出是某次运行的可移植副本，不会改变部署启动时检查的数据库行。绝不能通过删除历史让预检通过。

## 决定必须转换哪些内容 {#decide-what-must-be-converted}

仍处于活动状态的运行可以在当前部署的预发布版上完成。在运维上安全的情况下，让它们在维护窗口前完成。终态运行、为重放而保留的已关闭执行，以及无法等待完成的状态，都必须转换。迁移会清点两组内容，不删除任何一组。

试运行涵盖 Server 启动检查中由协议管理的接口：

- 工作流输入和输出、活动负载、命令、信号、更新、服务调用、更新验证任务和持久流引用；
- 内联单对象帧，以及历史事件中嵌套的显式负载封装；
- 外部存储负载引用，包括引用结构、编解码器、对象可用性、字节长度和 SHA-256 完整性。

客户管理的 memo、搜索属性、上下文和诊断映射不是编解码器声明，将保持原样。未知编解码器、未知 schema 指纹、损坏引用，以及固定 Avro Value schema 无法表示的值，都会被报告为不安全。发现不安全内容将阻止应用迁移。

## 所有权边界 {#ownership-boundary}

命令属于 Workflow PHP 包，但必须在拥有数据库连接和外部负载配置的进程中运行：

- **嵌入式 Laravel：** 在应用检出目录安装目标 Workflow 包，然后在应用的 Web、队列、调度器和维护进程均已停止时，运行应用的 `php artisan` 命令。
- **独立 Server：** 使用目标 Server 镜像中的一次性 shell 或任务，采用与部署相同的数据库、命名空间配置、凭据和外部负载挂载。转换成功前，保持正常引导钩子和所有 Server 进程停止。

不要让无关应用的检出目录连接该数据库。命名空间存储策略是完整性检查的一部分；进程无法读取外部对象时会报告不安全，不会猜测。

## 部署顺序 {#deployment-order}

1. 保留旧预发布版足够长时间，让选定的活动运行完成。随后停止所有数据库写入方：API 节点、Worker、调度器、引导任务和维护任务。
2. 按常规恢复策略为数据库和外部对象存储创建快照。保留旧应用或 Server 产物。
3. 安装或拉取包含 `workflow:v2:migrate-prerelease-history` 的目标产物，但不要启动。使用该产物执行试运行清点：

   ```bash
   php artisan workflow:v2:migrate-prerelease-history --dry-run --json
   ```

   退出码为零表示所有受影响的值均可安全转换。检查路径和受影响的运行 ID。非零退出码且 `unsafe_fields` 大于零时，升级被阻止；应修复存储访问，或继续使用旧预发布版。
4. 在持久存储上选择新的私有备份路径和新的私有证据目录。两者均不得已经存在。应用一次迁移：

   ```bash
   php artisan workflow:v2:migrate-prerelease-history \
     --backup=/secure/dw-prerelease-history-backup.json \
     --evidence-dir=/secure/dw-prerelease-history-evidence
   ```

   命令在开始更新前写入备份，并拒绝覆盖证据。它在一个事务中锁定并更新数据库行，保留工作流和运行标识，验证外部对象的哈希与大小，并保留所有原始外部对象。替代外部对象是按内容寻址的 Avro 副本。不会删除任何历史。
5. 等待命令完成。它会导出并严格重放每个受影响的保留运行，重建其摘要、等待、时间线、定时器和运行谱系投影，检查投影是否漂移，并再次清点负载。成功要求全部三项检查通过。将生成的重放和投影报告与备份一起保留。
6. 仅在迁移成功后执行目标版本的正常引导：

   ```bash
   php artisan server:bootstrap --force
   ```

   嵌入式 Laravel 应改为运行应用的常规迁移和引导流程。在任何新 Worker、API 节点、调度器或维护进程启动前，仅 Avro 负载预检必须通过。
7. 启动目标部署，通过正常运维接口验证就绪状态，以及一次保留运行的重放或查询。在整个回滚窗口内保留迁移资料。

## 回滚 {#rollback}

如果应用迁移、重放、投影验证或迁移后检查失败，升级就被阻止。保持所有写入方停止，并运行迁移输出的回滚命令。使用上述路径时，命令如下：

```bash
php artisan workflow:v2:migrate-prerelease-history \
  --rollback-from=/secure/dw-prerelease-history-backup.json \
  --evidence-dir=/secure/dw-prerelease-history-evidence
```

回滚会验证备份摘要和迁移状态，拒绝覆盖回滚证据，并拒绝恢复转换后又被修改的行。它以原子方式恢复原始数据库值，保留替代外部对象作为证据。随后恢复旧应用或 Server 产物。如果另一个写入方改变了状态，导致回滚被拒绝，请保持升级阻塞，并恢复步骤 2 中协调创建的数据库和对象存储快照。

回滚后，仅 Avro 的部署预期会再次预检失败。解决报告的不安全状态，创建新的备份和证据路径，并在重试升级前重新执行整个流程。
