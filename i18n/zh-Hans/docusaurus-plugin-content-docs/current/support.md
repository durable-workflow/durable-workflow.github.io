# 支持 {#support}

Durable Workflow 是一个开源项目，可依据 MIT 许可证免费使用。运行、交付它或用它构建生产系统都不需要商业协议。

这里最适合讨论：

- 使用问题
- 工作流建模建议
- 如何理解确定性与重放
- 分享想法和模式
- 报告错误或意外行为

## 部署支持边界 {#deployment-support-boundary}

Durable Workflow 的目标是无需先联系销售也能使用。公开发行版重点优化了大多数团队最先需要的部署路径：

- **本地开发和内部非生产环境**  
  在本地、局域网或共享预发布环境中运行软件包或独立 Server，让开发者能够快速运行工作流并迭代。

- **单节点生产环境**  
  在一台虚拟机、VPS 或内部主机上运行独立 Server，配备持久数据库、缓存、反向代理、备份和按角色限定权限的凭据。

- **小型集群部署**  
  在负载均衡器后运行 2 至 3 个无状态 API 容器，共享外部 MySQL 或 PostgreSQL、共享 Redis，独立扩缩 Worker，并且只运行一个调度器或维护运行器。

- **Kubernetes 清单**  
  如果团队已经运维 Kubernetes，并希望从 Kubernetes 原生配置入手，可使用提供的清单。

托管的 Durable Workflow Cloud 是独立的[托管编排服务](/docs/polyglot/cloud-control-plane)。Cloud 负责其运行时、持久化、单区域放置和恢复；客户运行 SDK 客户端和 Worker。客户不能将自托管 Server 接入 Cloud。多区域复制、区域故障转移和故障回切不属于当前 Cloud 契约。

公开发行版重点优化本地开发、单节点生产以及自托管指南中界定的小型集群契约。Kubernetes 清单面向已经运维 Kubernetes 的团队。小型集群在满足[滚动升级](/docs/rolling-upgrades)页面的全部保证时支持滚动升级。由操作人员执行区域故障转移的主备多区域方案仍属于支持团队指导下的评估内容，参见自托管指南中的[主备多区域](/docs/deployment#activepassive-multi-region)。已发布的 Helm chart 提供自助打包和发布路径；自定义 chart 修改、提供商基础设施、重复调度器、无 Redis 的多节点运行、提供商故障转移、主备或双活多区域、自托管自动区域故障转移，以及高级高可用拓扑仍需要支持团队参与，因为它们需要针对环境决定容量、数据库、网络、安全和升级方案。

具体支持矩阵、已发布镜像的 Compose 配方、原始 Kubernetes 清单的边界、就绪检查，以及何处需要支持团队介入，请参见[自托管部署指南](/docs/deployment)。

这一边界让自助路径保持简单，也在部署本身成为分布式系统工程时为深入协助留出空间。

## 商业支持（可选） {#commercial-support-optional}

对于需要更多保障或维护者级别专业知识的团队，我们提供商业支持和咨询。

使用 Durable Workflow **不需要**商业协议，无论是否购买商业支持，全部功能始终完全开源。

商业支持面向在生产系统中运行 Durable Workflow，并重视正确性、升级安全、部署拓扑和长时间运行执行语义的团队。

## 商业支持范围 {#what-commercial-support-covers}

商业支持由项目维护者主导，通常包括：

- **生产部署规划**  
  协助在单节点、范围明确的小型集群、Kubernetes 和支持团队指导的部署模式之间选择，包括数据库、缓存、反向代理、调度器和 Worker 拓扑。

- **容量、可靠性和升级规划**  
  协助审视容量假设、备份与恢复策略、引导与迁移顺序、发布安全和运维手册。

- **高级拓扑支持**  
  在支持团队指导下设计自定义 Helm chart 修改、提供商特定的 Kubernetes 基础设施、自定义覆盖配置、重复调度器、无 Redis 多节点模式、高可用部署、主备或双活多区域、自托管自动区域故障转移及同步跨区域复制。已发布的 chart 仍是自助安装路径；[自托管指南](/docs/deployment#activepassive-multi-region)保留主备架构和运维手册材料，供支持团队指导下的评估使用。独立的 [Cloud 托管运行时契约](/docs/polyglot/cloud-control-plane)说明托管服务的单区域放置、恢复和连接边界。

- **安全审查**  
  协助审查按角色限定权限的凭据、网络暴露、内部与公开端点、TLS 终止以及操作人员和 Worker 的访问边界。

- **工作流架构与设计审查**  
  指导正确建模工作流，包括活动边界、信号、收件箱/发件箱用法以及长时间运行的执行模式。

- **确定性与重放安全指导**  
  协助识别和避免非确定性行为、重放问题，以及可能随时间显现的细微正确性问题。

- **升级与版本策略**  
  协助安全升级、工作流版本管理，以及判断何时需要 `continue-as-new` 等模式。

- **复杂工作流行为调试**  
  协助诊断卡住的工作流、意外循环、信号处理问题及其他难以推断的运行时行为。

- **回移与补丁**  
  为受支持版本提供修复和回移，帮助避免维护私有分支。

- **自定义集成（另行约定）**  
  协助将 Durable Workflow 接入聊天平台、审批系统、内部 API 或可观测性工具等现有系统。

## 哪些团队适合商业支持 {#who-commercial-support-is-for}

以下情况通常适合商业支持：

- 在**生产环境**运行 Durable Workflow
- 为**多个团队或服务**部署独立 Server
- 构建**长时间运行或有人参与的工作流**
- 设计超出已验证单区域 2.0 运行边界的**集群、提供商特定或定制的 Kubernetes/Helm、主备或双活多区域，或自托管自动故障转移拓扑**
- 所在环境重视**正确性和升级安全**
- 需要**维护者级别专业知识**，而非通用咨询
- 希望避免分叉和长期维护风险
